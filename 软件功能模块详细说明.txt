一、项目总体架构
================================================================================

DataProcessor Pro 2.0 是一个离线光纤光栅(FBG)数据分析与报告生成桌面软件。
采用 巨石架构（monolithic），主窗口 main.py 承载所有 Tab 页面的生命周期。

【架构分层】
  ┌─────────────────────────────────────────────────────┐
  │  UI 层 (ui/)        — PyQt6 Widget, 信号驱动        │
  │  ├─ main.py         — 主窗口, Tab 管理器, 信号路由   │
  │  ├─ analysis_tab    — 数据分析/图表/统计             │
  │  ├─ compare_tab     — 多源数据对比                   │
  │  ├─ ai_diagnosis    — AI 诊断/多智能体审查            │
  │  └─ ...             — 其他 12 个 UI 模块             │
  ├─────────────────────────────────────────────────────┤
  │  后端引擎层 (py/)     — 信号处理/AI/报告生成           │
  │  ├─ multi_agent     — LangGraph 多智能体审查          │
  │  ├─ analyzer        — 时域/频域/滤波                  │
  │  ├─ formula         — 公式计算引擎                    │
  │  └─ report_builder  — Word/PPT 报告生成器             │
  ├─────────────────────────────────────────────────────┤
  │  核心数据模型 (core/)  — SSOT 数据定义                 │
  │  ├─ models          — Sensor/SensorSystem/FBG        │
  │  ├─ ai_client       — LLM 客户端单例                  │
  │  └─ report_engine   — AI 报告引擎                     │
  ├─────────────────────────────────────────────────────┤
  │  工具层 (utils/)      — 纯函数, 无 UI 依赖             │
  │  ├─ file_parser     — CSV/TXT/ENLIGHT 文件解析        │
  │  └─ data_cleaning   — 异常检测/缺失值填充              │
  └─────────────────────────────────────────────────────┘

【设计原则】
  1. SSOT (Single Source of Truth): 所有状态在 AppState 或 main.py 统一管理
  2. 信号驱动: UI Widget 之间不直接引用，通过 pyqtSignal 解耦
  3. 数据流防火墙: 光纤数据与非光纤数据通过 _is_fiber_data 严格隔离
  4. "卸妆"法则: 列名含单位后缀 (με) 时，必须先正则剥离再作为 key 匹配

2.1 core/models.py — 核心数据模型 (SSOT)
─────────────────────────────────────────
  文件大小: 19KB | 依赖: numpy, pandas

  【数据类 (dataclass)】
  ┌ GlobalParameter
    - 全局参数/共享常量，注入所有传感器公式的计算命名空间
    - 字段: name, value, unit, description
    - 策略: 全局参数打底，传感器局部常量覆盖

  ┌ DataTemplate
    - 数据文件格式定义（分隔符、跳过行数、列定义）
    - 字段: id, name, file_format, delimiter, skip_rows, columns[]
    - to_dict() 序列化为 JSON 配置

  ┌ CleaningRule
    - 数据清洗规则（相邻差值/nan/范围/负值/零值）
    - 字段: rule_type, enabled, threshold, min/max_value, fill_method
    - 填充方式: linear/mean/forward/backward/custom

  ┌ FBG (Fiber Bragg Grating)
    - 光纤光栅定义，对应一列原始波长数据
    - 字段: id (W1~W8), channel (列名), wavelength_min/max
    - is_valid() — 判断波长是否在有效范围

  ┌ Sensor (虚拟传感器)
    - 通过公式将原始波长差值转换为物理量
    - 字段: id, sensor_type, formula, constants, active, location
    - TYPE_PARAMS (ClassVar): 8 种传感器类型的参数映射
       应变(με), 温度(°C), 位移(mm), 倾角(°), 压力(MPa),
       双参量解耦(με/°C), 应变标定(με), 温度标定(°C)
    - get_unit() / get_name() — 从 TYPE_PARAMS 获取单位/名称

  ┌ SensorSystem (传感器系统管理器)
    - 管理 FBG 列表 + Sensor 列表，执行物理量计算
    - 【核心方法】calculate(df) → {sensor_id: [values]}
      1. 正则 W_PATTERN (^[wW](\d+)(?:-.*)?$) 匹配暗号列名
      2. 对每列计算波长差值 Δλ = λ_current - λ_reference
      3. 对每个活跃 Sensor，执行公式求值或解耦矩阵计算
    - _evaluate_sensor_formula() — eval 安全求值, 正则替换常量
    - _evaluate_decoupling() — 双参量解耦矩阵求解

  【类型定义】
  ┌ SensorType 字面量: 'strain'|'temperature'|... 共 8 种
  ┌ DecouplingConfig TypedDict: 解耦矩阵配置结构
  ┌ TimeDomainResult / FrequencyDomainResult TypedDict

  【独立函数】
  ┌ time_domain_analysis() — 均值/最大值/RMS/标准差
  ┌ frequency_domain_analysis() — FFT 频谱分析
  ┌ apply_filter() — 巴特沃斯低通/高通/带通滤波

七、数据流全景
================================================================================

【典型光纤光栅数据处理流程】

  1. 用户选择文件 → open_file()
  2. DataTemplate 识别文件格式 → parse_file() → current_data
  3. _auto_populate_fbgs() — 从列名提取 W\d+ 自动创建 FBG
  4. _insert_annotation_row_if_timestamp_exists() — 插入暗号标注行
  5. 用户在传感器 Tab 配置 Sensor (公式/常量/类型)
  6. calculate_sensors() → SensorSystem.calculate(df) → sensor_results
     ├─ W_PATTERN 正则匹配列 → 计算 Δλ
     ├─ 对每个活跃 Sensor 执行公式求值
     └─ 返回 {sensor_id: [物理量值序列]}
  7. analysis_tab.run_analysis()
     ├─ 光纤+物理量: 从 sensor_results 读取
     ├─ 光纤+原始: 固化波长差
     └─ 其它数据: 暗号列直读
  8. _update_chart_multi_sensors() 渲染图表
  9. _compare_curves() 双曲线对比分析
  10. 可选: 多源对比 Tab 跨文件对比

【AI 诊断流程】
  1. 用户选择模型 (在线/本地/Ollama)
  2. 选择项目文件 + 需求文件
  3. run_multi_agent() → LangGraph 三智能体流水线
     Data Scientist → Data Auditor(最多3轮) → Chief Scientist
  4. 生成结构化诊断报告 (JSON)

【报告生成流程】
  1. 用户选择报告类型 (Word/PPT) + 模板
  2. generate_outline() → LLM 输出大纲
  3. expand_section() → LLM 逐章展开
  4. WordBuilder/PPTBuilder → .docx/.pptx


================================================================================
八、关键技术方案
================================================================================

8.1 暗号标注系统
─────────────────
  在 DataFrame 首行插入标注行，用户用引号标记列角色:
  - '时间戳' — 标记时间列
  - 'w1-应变-梁底' — 标记数据列 (w{N}-类型-位置格式)
  解析: _parse_annotations() → data_cols + time_col + annotated_name_map
  隔离: 图表/统计/对比都通过 annotated_name 而非原始列名访问

8.2 数据流防火墙
─────────────────
  _is_fiber_data 双重判定:
  1. 列名含 FBG/ENLIG/光纤传感/W\d+
  2. 当前模板名含"光纤"/"ENLIGHT"
  非光纤数据: 锁定"物理量"下拉框并禁用
  光纤+原始: 波长差固化路径
  光纤+物理量: sensor_results 路径

8.3 "卸妆"清洗
───────────────
  列名可能含 "A1_应变(με)" 等 UI 展示后缀
  使用正则 re.sub(r'[\(（].*?[\)）]', '', name) 剥离
  get_best_match_column() — 双向去括号模糊匹配

8.4 X 轴防重叠方案
───────────────────
  不传递时间字符串给 ax.plot()
  改用 range(len(x)) 纯数值索引
  set_xticks + set_xticklabels 实现完整刻度控制
  np.linspace(0, N-1, 10) 精确定位 10 个刻度
  set_xlim(0, N-1) 消除 matplotlib 5% margin

8.5 下拉框-图例同步
───────────────────
  addItem(display_name, userData=raw_key)
  currentData() 读取原始 key 用于数据提取
  _to_display_name(): 先 _get_annotation_name() → 再剥离 w{N}- 前缀

8.6 Pandas 严格类型安全
───────────────────────
  禁止切片就地赋值 (lossy item setitem)
  全局类型提升: df = df.astype(object)
  "乐高式"拼接: pd.concat([top, new_row, bottom])

8.7 公式安全求值
───────────────────────
  eval(expr, {"__builtins__": {}}, local_vars)
  正则单词边界替换常量 (避免 k1 误匹配 k10)
  全局参数打底, 局部常量覆盖
  NaN/None 转为 float('nan') 确保 eval 不崩溃

8.8 多源时间对齐
───────────────────────
  numpy.interp 绝对时间插值
  基准网格: 公共时间列 → Unix 时间戳
  全局交集截断: max(各文件起始) ~ min(各文件结束)
  窗口首点归零消除静态偏置
