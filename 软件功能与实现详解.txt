1. 项目概述与架构
================================================================================

DataProcessor Pro 2.0 是一个基于 PyQt6 的光纤光栅 (FBG) 传感器数据分析平台，
集成了数据采集解析、信号清洗、物理量计算、多传感器标定、AI 辅助诊断、
知识库管理、报告自动生成等全链路功能。

技术栈:
  - 前端: PyQt6 (QMainWindow + QTabWidget 巨石架构)
  - 数据处理: Pandas 2.0+, NumPy
  - 公式引擎: asteval (安全向量化数学解释器)
  - 图表渲染: matplotlib + mplcursors
  - 文档生成: python-docx + python-pptx
  - AI 集成: LangGraph (多智能体状态机), OpenAI API, Ollama, llama-cpp-python
  - 语义搜索: sentence-transformers (all-MiniLM-L6-v2) + ChromaDB
  - 网页剪藏: trafilatura + markdownify + yt-dlp

项目拓扑:
  main.py               — 主入口，约 8800 行巨石架构
  ui/                   — 各标签页 UI 组件
  py/                   — 后端引擎
  core/                 — 核心数据模型 + AI 客户端 + 报告引擎
  utils/                — 文件解析 + 数据清洗
  state/                — 全局应用状态 (SSOT 单数据源)
  tests/                — 测试体系 (60+ 测试函数)
  wiki_vault/           — 本地知识库存储

类: AnalysisTabWidget(QWidget)
  文件: ui/analysis_tab.py:29

  功能:
    - 传感器选择列表 (多选/单选)
    - 物理量 vs 原始数据切换 (光纤数据专有)
    - matplotlib 图表渲染 (时序曲线)
    - 暗号标注模式 (非光纤数据的物理量识别)
    - 单位后缀剥离 ("卸妆"法则)

  关键常量:
    _UNIT_MAP: 传感器类型 → 单位后缀映射
      {'应变': '(με)', '温度': '(℃)', '位移': '(mm)', '挠度': '(mm)',
       '拉力': '(kN)', '应力': '(MPa)', '频率': '(Hz)', '索力': '(kN)'}

  核心实现:
    - _strip_unit_suffix(name): 正则剥离列名尾部括号单位 → 纯名称
      例: 'A1_应变(με)' → 'A1_应变'

    - get_best_match_column(target_col, dataframe): 双向去括号模糊匹配
      1. 清洗 target_col 和所有 DataFrame 列名
      2. 依次尝试完全一致 → 双向包含

    - _is_fiber_data(df, sensor_system): 判断是否为光纤波长数据
      → 决定是否允许"原始数据↔物理量"切换

    - _on_sensor_item_changed(): 传感器勾选变化 → 重新绘图

  数据隔离逻辑 (硬纪律 #4):
    光纤数据: 基于波长差 → SensorSystem.calculate() 计算
             → 允许"原始数据"/"物理量"切换下拉框
    通用数据: 已计算好的物理量 → 锁定为"物理量"模式
             → 强制读取 annotated_cols 暗号列

类: TemperatureCalibrationPage(QWidget)
  文件: ui/calibration_tab.py:1798

  功能:
    - 独立加载连续波长文件 (不写入主窗口 current_data)
    - 暗号自动识别 (从文件中标注行提取波长列 → 位置/类型映射)
    - Phase A: 平台检测 + 温度标定
    - Phase B: 双波长矩阵解耦分析

  核心属性:
    - _loaded_df: 独立加载的数据
    - _annotation_dict: {列名: 暗号字符串}
    - _annotation_groups: {prefix: {position→col}} 分组
    - _detection_params: 平台检测参数
      {
        rolling_window: 25,     # 滑动窗口大小
        std_percentile: 45.0,   # STD 百分位阈值
        min_plateau_samples: 180,  # 最少平台样本数
        head_trim_ratio: 0.70,  # 头部修剪比例
        sample_interval_s: 2.0, # 采样间隔
        hold_time_min: 6.0,     # 最短保温时间
      }

  Phase A 流程:
    1. 用户加载文件 → 暗号自动提取
    2. 打开 PhaseADialog → 指派列角色 (W1/W2...)
    3. 设定温度点 (min/max/step)
    4. PhaseAWorker 后台运行:
       a. 平台检测 (滑动窗口 STD 分析)
       b. KMeans 温度映射 (平台 → 设定温度)
       c. 灵敏度回归 (dλ/dT 线性拟合)
    5. 显示结果: S_eff 灵敏度表 + 回归图

  Phase B 流程 (需 Phase A 完成才可用):
    1. 打开 PhaseBDialog → 配置解耦系数
    2. PhaseBWorker 后台运行:
       a. 2×2 矩阵求逆解耦
       b. 应变/温度分离
    3. 显示: 解耦前后对比图 + 诊断四联图

  PhaseAWorker (PhaseAWorker 类):
    - 继承 QThread
    - 发射 progress / finished / error 信号
    - run() 调用 run_temperature_calibration()

  对话框状态对称恢复 (硬纪律 #5):
    - accept() + reject() 均触发 _write_state_to_main_page()
    - 存储 _phase_a_state / _phase_b_state
    - __init__ 末尾还原到 UI (含表格内容/样式/背景色)

15.4 SensorSystem — 传感器系统管理器 (核心计算引擎)
  属性:
    - fbgs: List[FBG] — FBG 列表
    - sensors: List[Sensor] — 传感器列表
    - reference_row: int — 参考行 (默认 0)
    - global_parameters: Dict[str, Any] — 全局参数池

  核心方法 calculate(df, fbg_columns=None) → Dict[str, List[Optional[float]]]:
    计算流程:
    1. 构建列数据字典 {col: np.ndarray}
    2. 正则自动探测 W-column (匹配 r'^[wW](\d+)(?:-.*)?$')
    3. 计算每行波长差值 Δλ = λ_current - λ_reference
       (NaN/Inf 安全守卫)
    4. 对每个活跃 Sensor:
       a. 解析公式中的变量 (正则提取大写字母开头标识符)
       b. 为每个变量查找对应的 FBG delta 列
       c. 调用 py/formula.py 的 calculate() (asteval 引擎)
       d. 结果 NaN/Inf → None
    5. 返回 {sensor_id: [value_or_None, ...]}

  解耦计算 _evaluate_decoupling(sensor, columns):
    2×2 矩阵求逆:
      | dL1 |   | Ke1  KT1 | | ε  |
      | dL2 | = | Ke2  KT2 | | dT |
      → 通过公式: ε = (KT2*W1 - KT1*W2) / (Ke1*KT2 - KT1*Ke2)

  全局参数管理:
    - set_global_parameter(name, value): 设置全局参数
    - get_global_parameter(name): 获取 (default 从 Sensor.TYPE_PARAMS 派生)

19. 温度标定引擎 (py/calibration/temperature_calibration.py)
================================================================================

文件: py/calibration/temperature_calibration.py

核心算法函数的纯函数模块。

19.1 detect_plateaus(df, cols, rolling_window, std_percentile,
                     min_plateau_samples, head_trim_ratio) → DataFrame
  平台检测算法:
    1. 滚动窗口 STD: df[col].rolling(rolling_window).std()
    2. 全局 STD 百分位阈值: np.percentile(all_std, std_percentile)
    3. 标记稳定段 (STD < 阈值)
    4. 合并相邻稳定段 (间隔 < min_plateau_samples)
    5. 过滤短段 (< min_plateau_samples)
    6. 头部修剪 (head_trim_ratio × min_plateau_samples)
    7. 返回平台 DataFrame (含时间/均值/STD/边界索引)

19.2 assign_setpoints(P, setpoints) → DataFrame
  温度平台 → 设定温度映射:
    - KMeans 聚类 (n_clusters = len(setpoints))
    - 按均值排序 → 与 setpoints 一一对应

19.3 regress_sensitivity(P, x_col, y_col) → dict
  线性回归: dλ vs T → 灵敏度 S_eff (pm/°C)
  返回: {slope, intercept, r2, rmse, T_base}

19.4 compare_given_vs_measured(name, given_KT, measured_S_eff, Ke) → dict
  标定值 vs 实测值对比:
    - diff = given_KT - measured_S_eff
    - apparent_strain = diff / Ke × 1e6 (ppm/°C)

19.5 decouple(dl1, dl2, Ke1, KT1, Ke2, KT2) → (eps, dT)
  双波长矩阵解耦:
    | dL1 |   | Ke1  KT1 | | ε  |
    | dL2 | = | Ke2  KT2 | | dT |
    求逆:   eps = (KT2·dl1 - KT1·dl2) / det
            dT  = (Ke1·dl2 - Ke2·dl1) / det
    其中 det = Ke1·KT2 - KT1·Ke2

  奇异矩阵守卫: det ≈ 0 → 返回 NaN (不抛异常)

19.6 run_temperature_calibration(df, ...) → dict
  全流程 orchestrator:
    1. detect_plateaus → 检测温度阶梯平台
    2. assign_setpoints → KMeans 温度映射
    3. regress_sensitivity → 各光栅 dL vs T 线性回归
    4. compare_given_vs_measured → 标定 vs 实测对比
    5. decouple → 双波长矩阵解耦
    6. 返回完整结果 dict

  返回结构:
    {
      "plateaus": DataFrame,       # 平台表
      "S_eff": {grating_col: {slope, r2, T_base}},  # 灵敏度
      "comparisons": [...],        # 标定 vs 实测对比
      "sensors": {name: {eps_orig, dT_orig, eps_corr, dT_corr, T_abs, ...}},
      "time_h": array,             # 时间轴 (小时)
    }

30. 关键数据流
================================================================================

30.1 标准数据分析流程:
  文件加载 → 解析 (parse_file / parse_enlight_file)
         → 数据预览 (DataTabWidget.update_data_table)
         → FBG 自动填充 (_auto_populate_fbgs)
         → 传感器定义 (SensorTabWidget)
         → 数据清洗 (clean_data)
         → 物理量计算 (SensorSystem.calculate)
         → 图表展示 (AnalysisTabWidget)

30.2 光纤数据特有流程:
  波长文件 → ENLIGHT 解析 → 暗号提取 (annotation)
         → 列名正则匹配 (W_PATTERN = r'^[wW](\d+)(?:-.*)?$')
         → Δλ 计算 (每行减参考行)
         → 物理公式求值 (asteval)
         → 结果展示 + 原始/物理量切换

30.3 温度标定流程:
  连续波长文件 → parse_enlight_file (暗号自动识别)
            → PhaseADialog (列角色指派: W1/W2/...)
            → 设定温度 (min/max/step)
            → PhaseAWorker 后台:
              → detect_plateaus (平台检测)
              → assign_setpoints (KMeans 温度映射)
              → regress_sensitivity (灵敏度回归)
            → PhaseBDialog (解耦系数配置)
            → PhaseBWorker 后台:
              → decouple (2×2 矩阵解耦)
              → 诊断四联图
            → 项目保存 (ProjectConfig)

30.4 应变标定流程:
  配置标定参数 (标距/模式/循环数/光栅类型)
         → 读数录入 (手填表 + Ctrl+V 批量粘贴)
         → StrainCalibrationWorker 后台分析
         → 结果: 灵敏度/线性度/重复性/迟滞
         → 加入已标定列表 (多传感器管理)
         → 应用标定系数到传感器 (会话级)

30.5 AI 辅助流程:
  用户输入需求 → AI 模型生成大纲 (AIClient)
              → 人工审核编辑大纲
              → AI 展开为完整报告
              → WordBuilder / PPTBuilder 渲染
              → 保存 .docx / .pptx

30.6 知识库流程:
  网络 URL → WebClipper.fetch_article (图文抓取)
           → download_and_replace_images (图片本地化)
           → save_to_wiki (Markdown 入库)
           → WikiFileSystem.add_page (索引更新 + 向量化)
           → ChromaDB 向量存储
           → 语义搜索 (query → embedding → ChromaDB → 结果)

附录 B: 关键设计模式与架构决策
================================================================================

  - 巨石架构: main.py ~8800 行，局部控制器抽离 (ui/ 目录)
  - SSOT: AppState 为单一状态源，不可变更新 (dataclasses.replace)
  - 信号驱动: 各 Tab 通过 pyqtSignal 通信，主窗口连接信号到槽
  - 公式隔离: asteval 安全沙箱，每次调用独立引擎防状态泄漏
  - 光纤/通用隔离: 严格 IF-ELSE 物理隔离 (光纤=原始+物理量, 通用=仅物理量)
  - 暗号系统: 数据文件中的引号标注行 → annotation → 自动识别列角色
  - 多智能体审查: LangGraph 状态机，支持驳回重做 (最多 3 轮)
  - 标定双阶段: Phase A (平台检测+灵敏度) → Phase B (解耦分析)
  - 项目持久化: ProjectConfig → JSON 文件，含温度+应变全量状态
  - 对话框状态对称: accept() + reject() 均写回状态，4条关闭路径全覆盖
  - 向量知识库: sentence-transformers 嵌入 + ChromaDB 存储 + 语义搜索
