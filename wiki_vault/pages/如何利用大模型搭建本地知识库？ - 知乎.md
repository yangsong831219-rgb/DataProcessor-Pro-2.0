# 如何利用大模型搭建本地知识库？

**142,279**

前阵子我做了一个决定：**狠心停掉了所有云端笔记软件的年费订阅。**

这倒不是心疼那几百块钱，而是我逐渐意识到一个问题：我平时最核心的工作复盘、深度学习体系和灵感碎片，凭什么要存在别人的服务器上？万一平台跑路或者关停服务，或者数据被泄漏，那就game over了。

而且传统云笔记的体验极其消耗精力。每次看完干货想记点东西，都要痛苦地纠结“这篇该放在哪个层级的文件夹里”，最后Notion里囤了几百篇笔记，全变成了互不相干的“垃圾场”。最要命的是，每次遇到复杂问题去问 AI，它都像个重度失忆患者，永远从零开始给你到处搜资料、临时拼凑，根本无法调用我已有的知识积累。

痛定思痛，我利用一天时间在 Mac 本地跑通了一套极简的自动化知识管理工作流。

这个工作流有几个优势：

![](assets/img_ed95057ea9c5.jpg)

**完全自动化**：你只管丢原始资料，AI 自动在后台帮你提炼逻辑、打好标签，不需要手动整理。**数据100%私有**：所有笔记和关系图谱全在本地硬盘，不上传任何服务器。**持久化增量积累**：知识会像神经元一样自我生长，不同文档提到同一个概念，会被自动缝合到一起。**极低的使用成本**：系统外壳全免费，只需按量支付大模型 API 费用（比如对接 DeepSeek），一年下来可能只要十几块钱。

如果你也受够了云端裸奔和低效的整理工作，花 10 分钟看懂这篇，直接把这套纯本地的自动化大脑搬回自己的电脑。

### 一、 系统架构设计：三件套的解耦与分工

真正好用的工具，绝不应该消耗你的精力去维护它。为了实现“零干预”的自动化，我把这套系统的“前端展示”、“后台执行”和“文件结构规范”进行了完全的解耦。

它的核心公式是：**Obsidian + Hermes Agent + LLM Wiki = 本地 AI 知识库**

```
┌──────────────────────┐ ┌──────────────────────┐
│ Hermes Agent (后台) │ ──────> │ Obsidian (前端展示) │
└──────────────────────┘ └──────────────────────┘
│ │
└───────> [ LLM Wiki 规范 ] <────┘
```

### 1. 前端渲染层：Obsidian

Obsidian 是一款免费、跨平台的本地双向链接笔记工具。在我的系统里，它不承担任何输入和整理的功能，**它仅仅作为我的“显示器”**。

它最核心的杀手锏是「双向链接」和「Graph View（关系图谱）」。在笔记里用方括号包裹一个词（如 `[[Claude-Code]]`

），它就会自动变成一个紫色链接。当你在后台不断往系统里喂资料时，Obsidian 会把这些孤立的文件瞬间渲染成一张极其震撼的网状星空图。一眼看过去，你就能知道哪些节点是知识枢纽，哪些是孤岛。

![](assets/img_359d4b8f9e9d.jpg)

### 2. 后台执行引擎：Hermes Agent

这是由开源研究团队 Nous Research 开发的自主 AI 代理（Agent），也是在终端里帮我干脏活累活的“自动化包工头”。

它拥有读取本地文件系统和调用终端命令的权限，背后可以无缝挂接你喜欢的任何大模型 API（如 DeepSeek 或 OpenAI）。它最强大的地方在于内置了学习循环。你只需要在终端给它下达大白话指令，它就会自动去读文档、提炼核心概念、生成排版精美的 Markdown 文件，并自动把双向链接连好。

![](assets/img_16c2147a3825.jpg)

### 3. 底层协议规范：LLM Wiki

如果只让 AI 瞎写，久而久之本地文件夹必定变成一坨乱麻。**LLM Wiki 不是一个独立的应用，而是一套写给大模型看的“文件目录 Schema”。**

它强行规范了知识的物理存放结构：

```
knowledge_base/
├── raw/sources/ # 原始素材（文章、文档原件）
├── wiki/entities/ # 实体页面（特定的人物、工具、项目）
├── wiki/concepts/ # 概念页面（核心的方法论、技术原理）
├── wiki/index.md # 自动生成的知识库索引
└── wiki/log.md # 系统的增量更新日志
```

有了这套标准，Hermes 在录入新资料时，就不会是简单地建个文件就完事，而是真正在本地给你持久化地构建一个属于你自己的维基百科（Wiki）。

### 二、 保姆级部署指南（以 macOS 为例）

整个配置过程不需要你懂复杂的代码，准备好你的 Mac，跟着下面的步骤一步步复制粘贴即可。

### Step 1：安装可视化前端（Obsidian）

- 打开浏览器，访问 Obsidian 官网（
`obsidian.md`

），下载 macOS 版本并安装。 - 打开 App，点击「创建新仓库 (Create new vault)」。
- 在你的电脑里找个本地路径（例如
`Documents/`

），新建一个名为`knowledge_base`

的文件夹，作为你的知识库根目录。

### Step 2：安装底层协议（LLM Wiki）

- 访问 GitHub，搜索并进入
`nashsu/llm-wiki`

开源项目。 - 在右侧的
**Releases**页面，下载最新的 macOS 安装包（`.dmg`

或`.tar.gz`

）。 - 将解压后的 App 拖入应用程序文件夹，双击打开。
- 点击右下角的设置图标，选择你的模型供应商（支持 OpenAI、Claude、DeepSeek 或任何 OpenAI 兼容接口），填入你的
**API Key**。

### Step 3：装载自动化大脑（Hermes Agent）

- 打开 Mac 自带的
**终端（Terminal）**。 - 复制并粘贴以下官方一键安装指令，然后按下回车：

`curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash`

- 等待安装完成后，运行以下命令重新加载终端配置：

`source ~/.zshrc`

- 运行配置向导来绑定你的大模型：

`hermes setup`

根据屏幕提示输入 `hermes model`

，选择你刚才在 LLM Wiki 里配置的同一个大模型供应商。

### Step 4：注入核心调教规则（核心重点）

为了防止 AI 乱动电脑里的其他文件，或者把日常闲聊的废话污染到知识库里，我们需要在第一次进入 Hermes 界面时，给它立下死规矩。

在终端输入 `hermes`

进入对话，然后**把下面这段话完整地发给它**（记得把路径换成你自己的实际 Mac 用户名）：

“我的本地知识库目录是：`/Users/你的Mac用户名/Documents/knowledge_base`

。请你作为知识库管家，严格遵守以下使用规则：

- 只有当我明确输入‘写入知识库’或‘导入知识库’时，才允许调用 llm-wiki skill 执行写入操作。
- 只有当我明确输入‘结合知识库’或‘根据知识库回答’时，才允许先检索本地知识库再进行回答。
- 所有生成的知识页面必须严格使用标准的 Markdown 语法，并且使用
`[[双向链接]]`

连接相关概念。 - 必须完全遵循 LLM Wiki 的文件结构规范（raw/sources, wiki/entities, wiki/concepts）来管理文件。”

看到 Hermes 回复确认后，整套系统的底层闭环就彻底完成了。

### 三、 日常极客工作流演示：只用两句“咒语”

搭好这套架构后，你就可以把 Obsidian 彻底缩小在后台，或者把它当成一个单纯的“星空看盘”。日常的知识管理，你只需要在终端里呼唤 Hermes，用两句 Trigger（触发词）来操控一切。

### 1. 无脑入库（Write 触发）

当你在推特、即刻或者技术博客上看到一篇信息密度极高的干货，或者自己写完了一篇杂乱的项目复盘，直接打开终端对 Hermes 说：

“写入知识库：[直接粘贴你的乱七八糟的文本内容]”

这时候你就可以去喝杯咖啡了。Hermes 收到带有触发词的指令后，会自动激活内置的 `llm-wiki`

技能。它在后台自己阅读、分析、洗稿，把里面的工具提取出来放进 `entities/`

，把核心方法论提取出来放进 `concepts/`

，自动打好 `[[双向链接]]`

，最后更新索引。

整个过程**不需要你手动点击任何图形界面，文件丢进去自动成网**。

### 2. 精准检索（Query 触发）

当你在写方案、找灵感，或者需要基于过往积累做决策时，不要去百度或者让普通的 AI 瞎搜。直接在终端对 Hermes 说：

“结合知识库：根据我们已有的技术方案和复盘笔记，帮我评估一下 A 架构和 B 架构的核心区别，并列出优缺点。”

这时候，AI 会立刻化身你个人的超级档案员，精准遍历你本地硬盘里的专属资料池，调用结构化的 Wiki 知识，给你给出一个带文档出处和来源标注的深度回答。

而在日常普通对话中，如果你只是问它“今天天气怎么样”或者“这段代码怎么写”，它绝对不会去碰你的本地知识库，从而保证了你的私人 Wiki 永远干净、纯粹、没有噪音。

### 四、 写在最后

在信息过载的时代，最悲哀的事情莫过于：**我们花费了大量的时间去“收集”知识，又花费了等量的时间去痛苦地“分类和排版”知识，最后却从未真正“使用”过知识。**

这套系统的本质，就是用工程化的思维把繁琐的格式整理交给了机器，把昂贵的数据主权拿回了自己手里。它让创作者和研究者能够把 100% 的精力，彻底解放出来去专注于最核心的“提问与探索”。

大家在 Mac 上跑配置或者修改自定义规则时，如果遇到任何路径报错或者 API 链接问题，**直接在评论区带上截图或者错误码留言，我看到后随时帮大家 debug。**
