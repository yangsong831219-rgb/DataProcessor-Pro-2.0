核心内容提炼：从“提示词”到“闭环”的范式转移
在2026年6月初，Anthropic 的 Claude Code 负责人 Boris Cherny 和知名开发者、OpenClaw 创始人 Peter Steinberger 几乎在同一时间提出了一个震撼AI开发界的共识：“不要再手动写提示词（Prompt）了，你的工作应该是设计闭环（Loops）。”
他们发言的核心思想可以总结为以下三个维度：
停止对话，开始建构系统（Stop Prompting, Start Looping）： 过去的AI使用方式是“一问一答”的聊天（即传统的 Prompting）。而他们指出，未来高价值的工作是编写一个 Loop（递归闭环）。在这个闭环中，你只需设定“终极目标”和“验证标准”，AI 系统会自动生成中间所需的各种提示词，不断自我纠错，直到任务彻底完成。
系统级的自动化验证（Verification is the new bottleneck）：
Peter Steinberger 分享了他管理开源项目的做法：他编写了一个简单的循环脚本，每5分钟唤醒一次，自动去 GitHub 抓取新问题，然后调度多个 AI Agent 并行处理。AI 自动写代码、自动跑测试、遇到报错自动把报错日志作为新的 Prompt 喂给自己修改。在这个过程中，人类彻底退出了“执行层”，只在最后负责最终代码的“审核与合并”。
杠杆的转移（用算力换人力）：
Boris Cherny 提到，现在他几乎不直接和 Claude 说话，他的职责变成了“编写控制 Claude 的循环逻辑”。一个闭环可能为了解决一个复杂问题，在后台让几个 Agent 自我对话上百次。虽然这会大幅增加 Token（算力）的消耗成本，但却成百上千倍地放大了工程师的个人产出。
作为一个普通人，如何学习和应用？（具体做法推荐）
即使你不写代码，这种“Loop”思维也能完全降维应用到日常工作（如写作、设计、数据分析、营销策划）中。以下是具体的落地做法：
1. 思维方式转变：从“当监工”变为“建流水线”
旧做法（监工模式）： “帮我写一份营销文案” -> 发现不好 -> “语气再活泼一点” -> 发现太长 -> “缩短到300字”。（人类处于循环之中，耗时费力）
新做法（流水线模式）： 不再做“挤牙膏”式的沟通。你需要把工作拆解为一个带有自我检验环节的系统。
2. 搭建你的“五步工作闭环”
你可以利用现有的工作流工具（如 Coze, Dify，或者 ChatGPT/Claude 的高级工作流），按照以下五个节点构建你的 Loop：
发现 (Discovery)： 设定触发器。比如“每周一早上读取竞品网站更新”。
计划 (Planning)： Agent 1 负责梳理目标，制定本周分析大纲。
执行 (Execution)： Agent 2 根据大纲撰写分析报告草稿。
验证 (Verification)（最核心的一步！）： 设置一个独立的 Agent 3（扮演严苛的审核员）。给它一套硬性规则：“检查报告是否包含数据图表、字数是否低于800字、是否有错别字。”
迭代 (Iteration)： 告诉系统，如果 Agent 3 判定不合格，直接把修改意见退回给 Agent 2 重写。全过程不要来烦你，直到 Agent 3 判定完美，再把最终报告发给你。
3. 警惕“闭环陷阱”：先半自动，后全自动
虽然全自动闭环听起来很美，但由于 AI 在后台会反复试错，全自动循环极其燃烧 Token 成本。
具体建议： 作为初学者，先设计“人在环中（Human-in-the-loop）”的半自动系统。即在“验证”进入下一次“迭代”前，加一个人类确认按钮。当你发现 AI 的自循环通过率很高、不会陷入死循环烧钱时，再将控制权彻底移交给 AI 调度器。
