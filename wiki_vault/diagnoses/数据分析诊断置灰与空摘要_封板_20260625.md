## 根因

`AnalysisProvider` (`core/data_providers.py:598-632`) 的 `is_available` 和 `get_summary` 都读 `main_win.sensor_results`：

- `sensor_results` 是光纤公式配置模块 (`calculate_sensors`) 的产物，FBG 数据需手动点"计算"才写入
- 数据分析页的图表/统计数据源是 `analysis_tab_widget._current_data`，与 `sensor_results` 无关
- `_push_annotation_sensor_results` 被 `has_fbg` 守卫拦截（FBG 数据下从不执行）

→ 判据张冠李戴：**fenix 页有数据但 provider 读错了属性**。

溯源详见 `docs/数据分析诊断置灰溯源.md` + `docs/数据分析置灰二次溯源.md`。

## 修法

**两个改动，同一文件**

### 1. `AnalysisProvider.is_available` — `data_providers.py:602-607`

```python
# 改前: 读 main_win.sensor_results（产能模块属性）
def is_available(self, main_win):
    sr = getattr(main_win, 'sensor_results', None)
    return bool(sr)

# 改后: 读 analysis_tab_widget._current_data（数据分析页数据源）
def is_available(self, main_win):
    atw = getattr(main_win, 'analysis_tab_widget', None)
    if atw is None:
        return False
    data = getattr(atw, '_current_data', None)
    return data is not None and not data.empty
```

### 2. `AnalysisProvider.get_summary` — `data_providers.py:609-680`

改前：读 `sensor_results` → FBG 数据下为空 → 注入 "无传感器计算结果"

改后：
- 读 `analysis_tab_widget._current_data`
- 用 `is_plottable_data_column` 过滤列（排除 `_anomaly` / `Timestamp` / 非数值）
- 从 `main_win.current_annotation` 取暗号名映射
- 逐列调 `compute_time_series_features` 输出统计特征
- `budget_chars` 自然截断，截断时显式标注 `(仅显示前 N 列，共 M 列，余略)`

### 3. 撤死代码 — `main.py:2668`

撤除中途补的 `self.sensor_results = sensor_results`（被 `has_fbg` 守卫拦截的死代码）。

## 弯路登记（诚实）

本批栽了两轮：

1. **第一轮**：补 `main.py:2668 self.sensor_results = sensor_results`，但该函数有 `has_fbg` 守卫（FBG 数据下拦截），补的是死代码。单测用 `has_fbg=False` 绕过守卫 → 误以为过。

2. **第二轮**：改 `is_available` 读 `_current_data`（数据分析项亮了），但 `get_summary` 仍读 `sensor_results` → 勾选后注入空摘要 → 模型回 "统计结果缺失"。

**根子**：`py/` 项目目录与 pip `py` 包名冲突 → 新单测无法被 pytest 收集 → 只能 standalone 跑 → 单测绿 ≠ 真机对。本会话因此多栽数轮。
