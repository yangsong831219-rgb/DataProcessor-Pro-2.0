# AI客户端单例重置时 api_key 泄漏 (预存缺陷)

**日期**: 2026-06-24
**状态**: 积压（待单独修改，不混入当前批次）
**严重度**: 中 — 有"本地路径可能触及残留在线密钥"的潜在红线风险

## 现象

`TestConfigureOnline::test_configure_makes_available` 失败：
```
assert not client.is_available()  →  assert not True
```
该测试在 `AIClient._instance = None` 后创建新实例、切 `_backend='online'`，期望 `is_available()→False`（因尚未配置在线密钥），实际返回 `True`。

## 根因链

1. `AIClient.__init__` (core/ai_client.py:177-178) 用 `hasattr(self, '_initialized')` 守卫单例只初始化一次。
2. 当 backend='local' 时，`__init__` 从配置文件读取 `api_key`（line 189: `_default_key = str(_lc['api_key'])`），本地占位值如 `"not-needed"` 是 truthy 字符串。
3. 测试设 `_instance=None` 后调用 `AIClient()` → `__new__` 创建新实例 → `__init__` 正常执行（新实例无 `_initialized`）→ `api_key` 被设为本地占位值。
4. 测试手动切 `_backend='online'`，但 `is_available()` (line 252) 对 online 后端检查 `bool(self.api_key)` → 残留的本地占位 api_key 是 truthy → 误返 True。

更深层问题：`_fresh_client()` (tests/test_ai_client_backend.py:28-38) 用 `object.__new__` 绕过 `__new__` 创建裸实例。若未先 `del _initialized`，`__init__` 会提前 return 并跳过所有属性清空，旧单例的 api_key/base_url/model_name 全部泄漏到"新"实例。

## 涉及位置

| 文件 | 行号 | 符号 |
|------|------|------|
| core/ai_client.py | 170-179 | `AIClient.__init__` — `_initialized` 单例守卫 |
| core/ai_client.py | 216-241 | `AIClient.configure_online` — 就地更新，不清 local 残留 |
| core/ai_client.py | 243-252 | `AIClient.is_available` — online 分支仅查 api_key truthiness |
| tests/test_ai_client_backend.py | 28-38 | `_fresh_client` — 测试辅助，需手动删 `_initialized` |

## 潜在红线风险

在"本地诊断"场景中，如果单例重置不彻底（`_initialized` 未清除），本地路径可能带着残留的在线 api_key 执行，在你最不希望的地方触发在线调用。这与"本地诊断绝不使用在线密钥"的隔离红线擦边。

## 修复方向（不在此批次执行）

- `configure_online()` / `configure_local()` 切换后端时显式清空对端敏感字段（api_key 等）
- 或引入显式 `reset()` 方法统一处理单例重建
- 测试侧：`_fresh_client()` 的 `del _initialized` 是 workaround，应与生产代码的 reset 对齐
