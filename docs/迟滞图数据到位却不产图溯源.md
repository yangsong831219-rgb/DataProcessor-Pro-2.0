## 1. 迟滞图生成分支

### 1.1 代码位置

`core/chart_bundle.py:400-419`

```python
_hyst_made = 0                                         # 400
for hs in cd.get('hyst_sensors', []) or []:            # 401  ← 迭代 6 个元素
    try:
        T_arr = np.array(hs['T_abs'], dtype=float)      # 403

        save_figure(fig, png := _os.path.join(...))      # 409
        manifest.add(...)                                 # 410
        _hyst_made += 1                                   # 411  ← 增加计数
    except Exception as e:
        _skipped.append(f"hyst({e})")                    # 413  ← 异常 → 进 skip
        warnings.append(...)                              # 414

if not cd.get('hyst_sensors'):                            # 415  ← 列表为空
    _skipped.append("hyst_loop(no hyst_sensors)")         # 416
    warnings.append("该记录无迟滞回线数据，跳过迟滞图")     # 417

if _hyst_made:                                            # 418  ← 有产出
    _made.append(f"hyst_loop x{_hyst_made}")              # 419
```

### 1.2 三条路径对应 made/skipped 情况

| 路径 | 条件 | made | skipped |
|------|------|------|---------|
| 成功 | `valid.sum() >= 3` 且出图无异常 | `hyst_loop xN` | 无 |
| 内层静默跳过 | `valid.sum() < 3` → `continue`（`line 405`） | 无 | **无** ← 唯一 |
| 异常 | `hs['T_abs']` KeyError 或 `np.array` 转换失败 | 无 | `hyst(...)` |
| 列表空 | `cd['hyst_sensors']` 不存在/为空 | 无 | `hyst_loop(no hyst_sensors)` |

**关键发现：`valid.sum() < 3 → continue` 是唯一既不进 `_made` 也不进 `_skipped` 的路径。** 其他三条路径都至少会出现在 `_skipped` 中。

## 2. 为什么 hyst_sensors=6 却没进生成分支

### 2.1 排除 (a) if 条件没覆盖

不对。`cd.get('hyst_sensors', []) or []` — 6 元素列表，truthy → for 循环一定进入。`if _hyst_made` 和 `if not cd.get('hyst_sensors')` 在外层，执行不受影响。

### 2.2 排除 (b) 被前面 return/continue 截断

不对。`gen_charts_from_bundle` 函数结构平坦：

```
line 330-347: calib_lin 块
line 349-363: ts_cleaning 块
line 365-377: compare_ol 块
line 379-398: corr_scatter 块
line 400-419: hyst 块        ← 独立，无前置 return
line 421:     print DONE     ← 印证执行到末尾
```

没有 `return`、没有 `raise`、没有把 hyst 包在 `if` 里的外层条件。各块独立，失败只 catch 不 re-raise。

### 2.3 排除 (d) 异常被 try/except 吞

不对。`except Exception as e:`（`line 412`）会 `_skipped.append(f"hyst({e})")`。如果异常发生，skipped 里一定出现 `hyst(...)`。但实际 skipped 里没有任何 hyst 字样。

### 2.4 确认 (c) 所有 6 个 sensor 的 valid.sum() < 3

**这是唯一匹配的解释。** for 循环确实迭代了 6 次，但每次 `valid.sum() < 3` → `continue` 静默跳过。`_hyst_made` 保持 0 → line 418 不触发；`hyst_sensors` 非空 → line 415 不触发。结果：print DONE 时 made/skipped 均无 hyst。

## 3. made/skipped 日志的完整性

### 3.1 两条列表的记账规则

是管账完整还是漏记？逐块核查：

| 块 | made 记在哪 | skipped 记在哪 | 有无不记账路径 |
|----|-----------|---------------|-------------|
| calib_lin | 339 | 344 (异常) / 347 (空) | 无 |
| ts_cleaning | 358 | 360 (异常) / 363 (空) | 无 |
| compare_ol | 372 | 374 (异常) / 377 (空) | 无 |
| corr_scatter | 398 (汇总) | 393 (异常) / 396 (空) | **有**：内层 `continue`（`line 384`）静默 |
| hyst_loop | 419 (汇总) | 413 (异常) / 416 (空) | **有**：内层 `continue`（`line 405`）静默 |

**corr_scatter 有同样的设计缺陷**：`line 384` 的 `if len(sa) < 2 or len(sb) < 2: continue` 也是静默跳过。如果 compare_pairs 存在但各 pair 的源数据为空，corr 和 hyst 一样会"神秘消失"——这与真机日志一致：corr_scatter 也同样没出现。

**结论：`_skipped` 只记录"整个分支因缺数据而跳过"和"异常"，不记录"数据存在但单条不满足质量门槛"的静默丢弃。**

### 3.2 hyst 的结构性静默路径

```
line 401: for hs in [...6 items...]:     ← 进入
line 403:   T_arr = np.array(hs['T_abs']) ← 数据存在
line 405:   if valid.sum() < 3: continue  ← 静默跳过
            ↑ 此处既不记账也不 warning
line 418: if _hyst_made:                  ← _hyst_made=0 → 跳过
line 416: 已在上方, hyst_sensors 非空 → 跳过
```

## 5. 根因指向

**根因 (c) — 所有 6 个 sensor 在 `valid.sum() < 3` 处被静默跳过。**

证据链：

| # | 事实 | 排除项 | 证据 |
|---|------|--------|------|
| 1 | `hyst_sensors=6` → for 循环进入 | (a) if 条件没覆盖 | `line 401` — `or []` 兜底，列表非空 |
| 2 | made 中无 hyst | (b) 被前面截断 | 函数结构平坦，`line 421` print 证明执行到末尾 |
| 3 | skipped 中无 hyst | (d) 异常被吞 | `line 412-414` 必然写 `_skipped` |
| 4 | 唯一既不 made 也不 skip 的路径 | — | `line 405` — `if valid.sum() < 3: continue` |
| 5 | 字段名对齐 | 不是读/写不对齐 | 4.3 对齐表确认 |
| 6 | 同现象也发生在 corr_scatter | 佐证设计模式一致 | `line 384` — 同样的 silent continue |

**`valid.sum() < 3` 的来源**：`np.isnan(T_arr) | np.isnan(eps_arr)`。如果 `T_abs` 或 `eps_orig` 的数组中大部分是 NaN，`valid.sum()` 会极小。NaN 可能来自：
- Worker 的 `decouple()` 输出（本应全是有效 float）
- `dT_corr + T_base` 若 `dT_corr` 含 NaN → `T_abs` 也含 NaN
- JSON 序列化/反序列化过程中 NaN 丢失或转换异常

**不能从只读进一步确认**：NaN 来源需用真实数据验证（在 `gen_charts_from_bundle` 入口加 `print(f"[DIAG] hyst_sensors[0] T_abs[:10]={hs['T_abs'][:10]}")` 即可定位）。但根因机制已明确：`line 405` 的静默 `continue` 是唯一匹配的路径。

### 与 corr_scatter 的同症对照

corr 也是 6 个 compare_pairs（数据存在），但既不在 made 也不在 skipped。同样是因为 `line 384` 的 `if len(sa) < 2 or len(sb) < 2: continue` 静默跳过。两个块的"数据存在但不满足质量门槛时静默丢弃"是同一个设计模式。
