### 16. 迁移到目标架构评估

**(i) 可直接复用为生产者的现有函数**:

| 函数 | 复用方式 | 评估 |
|------|---------|------|
| `gen_charts_from_bundle` | **直接作为生产者实现** | ✅ 已从 bundle 字典取数 → 出 PNG → save_figure，天然符合"生产者"模式 |
| `ChartBundle.from_providers` | 从 UI 采数据 → 入口 | ✅ 需要在诊断完成后瞬时调用 |
| `save_figure` | 存 PNG | ✅ 可复用 |
| `FigureManifest.add` | 记录图清单 | ✅ 可复用 |
| `calibration_chart_tool.render_*` | 需适配成 PNG 文件版本 | ⚠ 当前输出 BytesIO，需改接 save_figure/file path |

**(ii) 必须砍掉或合并的岔路**:

| 岔路 | 处理 | 原因 |
|------|------|------|
| `_generate_charts_from_providers` | 砍/锁定不再新调用 | 与 bundle 路径重叠且图不全 |
| 诊断保存 → `gen_charts_from_diagnosis` 到 `图片/` | 重定向到图仓 | 当前与报告重复产图 |
| INSERT_IMAGE 锚点 vs "图N"引用 | 统一为 manifest 驱动 | 两套机制增加复杂度 |
| PhaseBChartsDialog 独立渲染 | 改为消费图仓 PNG | 或者保持独立 (实时交互需要) |

**(iii) 风险最高的耦合点**:

1. **`ChartBundle.from_providers` 依赖实时 UI 状态** — `_current_data`/`_phase_b_state`/`_last_comparison` 等必须在诊断保存瞬间非空。若切换到"图仓→离线索图"，需确认这些端口在产图时都可用。
2. **`eps_orig` vs `eps_corr` 优先级反转** — `chart_bundle.py:184`，不改则 hyst 永远 NaN。
3. **粒度错配** — `hyst_sensors` 存 ~98450 点逐行监测数据，非台阶聚合。当前 `make_hysteresis_loop` 接受任意输入所以能画，但物理含义和工作量都不对（98450 个散点 vs ~100 个台阶点）。
