## 2. 存盘格式与落点

### 2.1 格式

**JSON** — `json.dump(..., ensure_ascii=False, indent=2)`

```python
# py/calibration/project_config.py:133-140
def save(self, dir_path: str | None = None) -> str:
    """保存到 {dir_path or PROFILES_DIR}/{name}.json"""
    target_dir = dir_path or PROFILES_DIR
    os.makedirs(target_dir, exist_ok=True)
    self.last_modified = datetime.now().isoformat()
    path = os.path.join(target_dir, f"project_{self.name}.json")
    with open(path, "w", encoding="utf-8") as f:
        json.dump(self.to_dict(), f, ensure_ascii=False, indent=2)
    return path
```

**无 schema 版本字段**。`ProjectConfig` dataclass 的字段不含 `schema_version`。

```python
# py/calibration/project_config.py:83-99
class ProjectConfig:
    ...
    name: str = ""
    created_at: str = ""
    last_modified: str = ""
    temperature: dict | None = None
    strain: dict[str, StrainSubConfig] = field(default_factory=dict)
```
`grep "schema\|version\|v1\|v2" py/calibration/project_config.py` → **无匹配**。

### 2.2 存储目录

```python
# py/calibration/project_config.py:20-23
PROFILES_DIR = os.path.join(
    os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))),
    "calibration_profiles",
)
```
即 `<项目根>/calibration_profiles/`。

### 2.3 文件名规则

`project_{用户输入名称}.json`。  
例如: `project_项目_20260624_1530.json`

### 2.4 顶层 JSON 结构

```json
{
  "name": "...",
  "created_at": "...",
  "last_modified": "...",
  "temperature": { ... } | null,
  "strain": { "A1": { ... }, "A2": { ... } }
}
```

## 3. 保存时：写入字段清单

`capture()` 方法 (`py/calibration/project_config.py:240-337`) 从两个页面提取数据。

### 3.1 温度段 (`temperature` dict)

| 字段 | 来源 | 类型 | 来源分类 |
|------|------|------|----------|
| `file_path` | `tp.file_path_edit.text()` | 字符串 | 【用户输入项 — 文件路径】 |
| `file_format` | `tp._annotation_meta.format` | 字符串 | 【派生 — 解析器自动检测】 |
| `annotation` | `tp._annotation_dict` | `{列名: 暗号}` | 【用户输入项 — 暗号补填表】 |
| `temp_min` | `tp._phase_a_state.tmin` | float | 【用户输入项 — 阶段A对话框温度范围】 |
| `temp_max` | `tp._phase_a_state.tmax` | float | 【用户输入项 — 同上】 |
| `temp_step` | `tp._phase_a_state.tstep` | float | 【用户输入项 — 同上】 |
| `detection_params` | `tp._detection_params` | dict | 【用户输入项 — 平台检测参数(窗口/百分位等)】 |
| `s_eff_results` | `tp._last_result.S_eff` | `{列名: {slope, r2, T_base}}` | 【派生/计算结果 — 阶段A灵敏度回归】 |
| `ke_table` | `tp._phase_b_state.ke_table` | `{传感器: {Ke1, Ke2}}` | 【用户输入项 — 阶段B Ke系数表】 |
| `decoupling_results` | `tp._phase_b_state.decoupling_results` | `{传感器: {e_mean, e_std, e_range, rating}}` | 【派生/计算结果 — 阶段B解耦诊断】 |
| `compensation` | `tp._phase_b_state.compensation` | `{传感器: {compensation_model, metrics, grade}}` | 【派生/计算结果 — 补偿流水线 LOOCV/评级】 |

> **注意**: `compensation` 字段**仅在 PhaseBDialog accept 时**通过 `_write_state_to_main_page()` (`ui/calibration_tab.py:2040-2046`) 调用了 `to_dict()` 转换为可序列化形式。若 Phase B 未运行或未 accept，此字段可能含不可直接 JSON 序列化的 Python 对象（`CompensationModel`/`CompensationMetrics`/`SensorGrade` dataclass 实例）。

**温度段门控条件** (`py/calibration/project_config.py:290-291`):
```python
has_temp_data = tp_annot or seff or ke_table or decoupling
if has_temp_data:
    temperature = { ... }
```
若 annotation / s_eff / ke_table / decoupling 四项**全空**，则 `temperature` 字段为 `None`（整段不存）。

### 3.2 应变段 (`strain` dict — `{传感器名: StrainSubConfig}`)

三个数据来源合并 (`py/calibration/project_config.py:312-331`):

```python
# 来源 1: self._strain_configs (页面活状态，全部传感器)
if hasattr(sp, '_strain_configs') and sp._strain_configs:
    for s_name, sub in sp._strain_configs.items():
        if isinstance(sub, StrainSubConfig):
            strain[s_name] = sub

# 来源 2: CalibrationTabWidget.project_config.strain (跨模块缓存)
if hasattr(sp, '_get_cal_tab_widget'):
    ctw = sp._get_cal_tab_widget()
    if ctw is not None and ctw.project_config is not None:
        for s_name, sub in ctw.project_config.strain.items():
            if s_name not in strain:
                strain[s_name] = sub

# 来源 3: 当前活跃传感器 (兜底)
if hasattr(sp, '_ke_results') and sp._ke_results and hasattr(sp, '_build_strain_subconfig'):
    sensor_name = sp._parse_sensor_from_grating_map()
    if sensor_name and sensor_name not in strain:
        sub = sp._build_strain_subconfig()
        strain[sensor_name] = sub
```

每个传感器对应一个 `StrainSubConfig` (`py/calibration/project_config.py:56-79`):

| 字段 | 来源 | 类型 | 来源分类 |
|------|------|------|----------|
| `sensor_name` | `_parse_sensor_from_grating_map()` → 从 grating_map 暗号推断 | 字符串 | 【派生 — 从光栅暗号的前缀提取】 |
| `sensor_mode` | `_config["grating_kind"]` 映射 | 字符串 | 【用户输入项 — 单栅/双栅锚固/双栅双工作】 |
| `gauge_length_mm` | `_config["gauge_length_mm"]` | float | 【用户输入项 — 标距】 |
| `n_cycles` | `_config["n_cycles"]` | int | 【用户输入项 — 加载循环数】 |
| `grating_map` | `_grating_map` | `{"G1": "A1-W1", "G2": "A1-W2"}` | 【用户输入项 — 备注行暗号映射】 |
| `readings` | `_levels` → `[{disp_mm, eps_theory}, ...]` | list[dict] | 【**部分**用户输入项 — 见 3.2.1】 |
| `ke_results` | `_ke_results` | `{"Ke1": 1.23, "Ke2": 0.98}` | 【派生/计算结果 — 应变标定拟合】 |
| `charts_meta` | 空 dict `{}` | dict | 【预留 — 始终为空】 |

#### 3.2.1 ★ 应变 readings 存盘内容的严重简化

`_build_strain_subconfig()` (`ui/calibration_tab.py:3158-3178`) 的读数提取：


**实际存盘内容**:
```json
[

  {"disp_mm": 0.016, "eps_theory": 200.0},
```

**未保存的读数数据**:
- `self._readings` — 完整原始波长读数 `{grating_idx: {cycle: {"load": [...], "unload": [...]}}}` **未保存**（此变量在 `_load_sensor_to_workspace` 中被置空为 `{}`）。
- `self._config["mode"]` — 张拉仅上升 / 张拉+退回 模式 **未保存**（加载时硬编码为 `"tension_only"`）。

## 4. 加载时：字段回填活状态

`restore()` 方法 (`py/calibration/project_config.py:340-524`) 分温度段和应变段两步回填。

### 4.1 温度段回填（Step 0–6）

#### Step 0: 重读源文件
```python
# py/calibration/project_config.py:354-368
src_path = t.get("file_path", "")
if src_path and os.path.isfile(src_path):
    from utils.file_parser import parse_enlight_file
    df, file_annot, meta = parse_enlight_file(src_path)
    tp._loaded_df = df
    tp._annotation_meta = meta
    tp.file_path_edit.setText(src_path)
```
若文件已不存在（路径失效），`tp._loaded_df = None`，不崩。

#### Step 1: annotation — 三层合并
```python
# py/calibration/project_config.py:370-398
# 以文件暗号为底
merged = dict(file_annot) if file_annot else {}
for col_name, profile_val in profile_annot.items():
    if col_name in tp_dirty:
        # 用户手动编辑过 → 锁定, 保持用户值
        ...
    elif col_name not in merged or not merged.get(col_name):
        # 文件无该列暗号 → 用 profile 值
        merged[col_name] = profile_val
```
优先级: **用户手改** (在 `_annotation_dirty` 集合中) > 文件自带暗号 > profile 存档值。

#### Step 3: Phase A — 灵敏度假数组
```python
# py/calibration/project_config.py:404-415
seff = t.get("s_eff_results", {})
if seff:
    tp._phase_a_done = True
    tp._last_result = {
        "S_eff": dict(seff),
        "wavelength_cols": list(seff.keys()),
        "plateaus": pd.DataFrame(),     # ★ plateaus DataFrame 不复原
        "df": tp._loaded_df,
    }
```
`plateaus` 置空 DataFrame — **平台散点数据不持久化，加载后无法重现回归散点图**。

#### Step 4: Phase B — 解耦假数组
```python
# py/calibration/project_config.py:419-435
if decoupling:
    sensors = {}
    for s_name, d in decoupling.items():
        is_single = s_name not in t.get("ke_table", {})
        sensors[s_name] = {
            "eps_corr": [d.get("e_mean", 0)] * 10,  # ★ 假数组: e_mean 重复 10 次
            "eps_orig": [], "dT_corr": [], "T_abs": [],
            "S1": 0, "S2": 0, "T_base": 0,
            "single_grating": is_single,
        }
    tp._phase_b_result = {"sensors": sensors, "time_h": np.array([]), "df": ...}
```
**`eps_corr` 是 `[e_mean] × 10` 的填充假数组**，原始解耦时序 `eps_orig`/`dT_corr`/`T_abs` 为空。时序数据完全丢失，四联图无法还原。

#### Step 5: 同步快照字典
```python
# py/calibration/project_config.py:438-452
tp._phase_a_state = {
    "annotation": ..., "annotation_dirty": ...,
    "groups": ..., "tmin": ..., "tmax": ..., "tstep": ...,
    "params": ..., "seff_result": tp._last_result,
}
tp._phase_b_state = {
    "ke_table": dict(t.get("ke_table", {})),
    "decoupling_results": dict(decoupling),
    "compensation": dict(t.get("compensation", {}) or {}),
}
```

#### Step 6: UI 按钮使能
```python
# py/calibration/project_config.py:455-473
if df_ready:
    tp.btn_phase_a.setEnabled(True)      # 阶段A按钮使能
    tp.btn_phase_b.setEnabled(tp._phase_a_done)  # 阶段B仅在A完成后使能
```

### 4.2 应变段回填

```python
# py/calibration/project_config.py:484-524
```

## 6. 应变读数录入对话框 — 表格结构与数据绑定

应变标定的核心输入界面是 `_open_readings()` 创建的独立对话框。理解其表格列布局、数据填充/提取路径，对于判断"保存/加载覆盖了什么、漏了什么"至关重要。

### 6.1 触发入口

**按钮** `📋 读数录入...` → `_open_readings()`  
`ui/calibration_tab.py:2937-2938`

```python
self.readings_btn = create_button("📋 读数录入...", self._open_readings, "secondary")
```

> 每次点击**新建独立 QDialog**，不存在跨次复用的持久表格。关闭时数据写回 `self._levels`、`self._readings`、`self._grating_map` 三个实例变量。

### 6.2 表格列布局 (`_build_table_columns`)

`ui/calibration_tab.py:3248-3269`

列顺序固定: **位移列 + 理论应变列 + 循环×光栅×方向**:

```python
def _build_table_columns(self):
    c = self._config
    is_return = c["mode"] == "tension_return"
    n_gratings = 1 if c["grating_kind"] == "single" else 2
    cols = ["位移(mm)", "理论应变(με)"]
    for ci in range(c["n_cycles"]):
        for gi in range(n_gratings):
            cols.append(f"G{gi+1}_C{ci+1}_张拉(nm)")
        if is_return:
            for gi in range(n_gratings):
                cols.append(f"G{gi+1}_C{ci+1}_退回(nm)")
    return cols
```

| 列索引 | 列名 | 编辑权限 | 内容 |
|--------|------|---------|------|
| 0 | `位移(mm)` | 可编辑 | 加载位移值 (`_levels`) |
| 1 | `理论应变(με)` | **只读** | 自动计算 `disp_mm / gauge × 10⁶` |
| 2+ | `G1_C1_张拉(nm)` ... | 可编辑 | 原始波长读数 (nm) |

列数 = 2 + `n_cycles × n_gratings × (1 or 2 取决于 mode)`。

### 6.7 两个读数字典的映射关系

存在**两套读数数据结构**:

| 名称 | 用途 | 存在位置 | 持久化至 `readings` JSON? |
|------|------|---------|--------------------------|
| `self._readings` | 原始波长 (用户输入) | 实例变量，对话框关闭时填充 | **否** |

## 7. 覆盖缺口

对照"一次完整手册录入需要填写的全部内容"，现有保存功能**未覆盖**的输入项:

### 7.1 应变标定 — 原始波长读数 (★ 最大缺口)

- **缺失内容**: 各光栅在各级位移下的原始波长读数，即 `self._readings = {grating: {cycle: {"load": [...], "unload": [...]}}}`
- **影响**: 加载项目后，用户打开"读数录入"对话框 → 表格显示位移/理论应变为空，波长读数列为全零。用户必须**重新手动逐格填写所有波长读数**。
- **当前存盘内容**: 仅保存 `_levels`（位移值）→ `readings[].disp_mm` + 派生值 `eps_theory`
- **证据**:
  ```python

  # 加载后 (ui/calibration_tab.py:3849)
  self._readings = {}  # ★ 置空
  ```

### 7.2 应变模式 (mode)

- **缺失内容**: `_config["mode"]` = `"tension_only"` 或 `"tension_return"`
- **影响**: 加载后始终强设为 `"tension_only"`；原为 `"tension_return"` 的项目丢失退回读数列配置
- **证据**:

## 8. is_available 关联

### 8.1 CalibrationProvider.is_available 定义

```python
# core/data_providers.py:265-273
def is_available(self, main_win: Any) -> bool:
    tp = self._get_temp_page(main_win)
    if tp is None:
        return False
    pa = getattr(tp, '_phase_a_state', {}) or {}
    pb = getattr(tp, '_phase_b_state', {}) or {}
    has_a = bool(pa.get('seff_result'))
    has_b = bool(pb.get('decoupling_results') or pb.get('compensation'))
    return has_a or has_b
```

### 8.2 保存流程与 is_available 的关系

**保存时** (`capture` 方法): 不读取、不写入 `is_available()`。`capture` 直接从 `tp._phase_a_state` 和 `tp._phase_b_state` 读字段，不通过 `CalibrationProvider`。

### 8.3 加载流程与 is_available 的关系

**加载时** (`restore` 方法): 写入了 `tp._phase_a_state` 和 `tp._phase_b_state`，这些字段恰好是 `is_available()` 的判断依据。

具体链路:
1. `restore()` Step 3 → `tp._phase_a_state["seff_result"] = tp._last_result` (`py/calibration/project_config.py:446`)
   - 如果 S_eff 数据存在 → `pa.get('seff_result')` 非空 → `has_a = True`
2. `restore()` Step 5 → `tp._phase_b_state = {"decoupling_results": ..., "compensation": ...}` (`py/calibration/project_config.py:448-452`)
   - 如果解耦或补偿数据存在 → `pb.get('decoupling_results')` 或 `pb.get('compensation')` 非空 → `has_b = True`

**结论**: 加载配置会**间接**设置 `CalibrationProvider.is_available()` 返回 `True` (通过写入 `_phase_a_state` / `_phase_b_state`)，但代码中**没有显式的** `is_available` 赋值语句。加载流程和 `is_available` 之间是隐式耦合：它们共享同一个底层状态字典。

### 8.4 UI 门控联动

加载流程 Step 6 使能了温度子页的阶段 A/B 按钮 (`py/calibration/project_config.py:465-473`):
```python
tp.btn_phase_a.setEnabled(True)
tp.btn_phase_b.setEnabled(tp._phase_a_done)
```

这些按钮状态与 AI 诊断中的 `CalibrationProvider.is_available` **无直接联动**。AI 诊断面板的"传感器标定"复选框由 `is_available()` 返回值控制 (`ui/ai_diagnosis.py` 中的 `_source_checkboxes`)，两者通过共享 `_phase_a_state`/`_phase_b_state` 隐式同步。
