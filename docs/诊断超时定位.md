## 1. 超时配置

### 1.1 HTTP 读超时 / 连接超时

同一处，online 和 local 共用同一个 `httpx.Timeout`：

```python
# core/ai_client.py:444-448 — non-streaming generate()
try:
    import httpx as _httpx
    _timeout: Any = _httpx.Timeout(120.0, connect=10.0)
except Exception:
    _timeout = None
```

```python
# core/ai_client.py:586-590 — 流式 generate_stream()
try:
    import httpx as _httpx
    _timeout: Any = _httpx.Timeout(120.0, connect=10.0)
except Exception:
    _timeout = None
```

```python
# core/ai_client.py:770-772 — generate_with_tools()
import httpx as _ttpx
_tmt: Any = _ttpx.Timeout(120.0, connect=10.0)
```

| 参数 | 值 | 含义 |
|------|-----|------|
| 读超时 (`read`) | **120.0s** | 单个 HTTP 请求的读取超时 |
| 连接超时 (`connect`) | 10.0s | TCP 连接建立超时 |
| 写/池化 | httpx 默认 | 未显式设置 |

### 1.2 在线 / 本地共用同一超时常量

`online` 和 `local` 后端路径完全相同——均创建 OpenAI SDK 客户端并传入同一个 `httpx.Timeout(120.0, connect=10.0)`。**不存在为本地慢模型调高的超时设置**。

## 2. 多智能体单轮上限

### 2.1 max_tokens 动态计算

每轮调用 `_invoke_llm` → `ai._safe_max_tokens()` → 动态计算：

```python
# core/ai_client.py:368-395
def _safe_max_tokens(self, system_prompt, user_prompt, requested):
    ctx = self._get_context_size()       # local → 8192 (或配置的 ctx_size)
    margin = 512
    prompt_est = self._estimate_tokens(system_prompt) + self._estimate_tokens(user_prompt)
    available = ctx - prompt_est - margin
    ...
    safe = max(512, min(requested, available))
    return safe
```

### 2.2 典型数值

从 DIAG 打印的真实数据：

```
model=qwen3.5-9b, ctx=8192, max_tokens=5946, prompt_est_tokens=1734, available=5946
model=qwen3.5-9b, ctx=8192, max_tokens=5098, prompt_est_tokens=2582, available=5098
model=qwen3.5-9b, ctx=8192, max_tokens=4130, prompt_est_tokens=3550, available=4130
```

三轮为 DS→advisor→chief，max_tokens 分别约 5946 / 5098 / 4130。

### 2.3 单轮最坏耗时 vs 读超时

```
最坏 max_tokens = 5946 tokens
本地 Qwen3.5-9B 生成速度 ≈ 9 tok/s

单轮最坏耗时 ≈ 5946 ÷ 9 ≈ 661 秒
```

**661 秒 >> 120 秒读超时。生成耗时远超 HTTP 读超时。**

`_invoke_llm` 调用 `ai.generate()` → 同步阻塞 → 120 秒后 httpx 触发 `ReadTimeout` → OpenAI SDK 抛出异常 → `classify_openai_error` 返回 `AIClientTimeoutError` → 无重试 → 异常直抛到 LangGraph 节点。

## 3. 取消链路

### 3.1 "Request timed out" → 客户端主动掐

`generate()` 非流式路径中，httpx 在达到 `read=120.0s` 超时后**客户端主动 raise ReadTimeout**。OpenAI SDK 将它包装后抛出。这是客户端行为——不是服务端（llama-server）断开。

### 3.2 LLM 调用不经过重试包装

```python
# py/multi_agent.py:121-127 — _invoke_llm 直接调用 generate()
return ai.generate(
    prompt=user_prompt,
    system_prompt=system_prompt,
    temperature=0.3,
    max_tokens=max_tokens,
    enable_thinking=False,
)
```

`ai.generate()` 不包含重试逻辑——重试在 `generate_with_retry()` (`core/ai_client.py:904-959`) 中，但 `_invoke_llm` 不使用它。超时后异常直接冒泡到 LangGraph 图节点 → `MultiAgentThread.run()` 的 `except Exception` → `error_signal`。

### 3.3 流式取消 vs 同步调用中断

```python
# core/ai_client.py:538-548 — cancel_current_stream()
def cancel_current_stream(self) -> None:
    if self._stream_response is not None:
        try:
            self._stream_response.close()
        except Exception:
            pass
        self._stream_response = None
```

此方法仅对流式 `generate_stream()` 路径有效。`_invoke_llm` 用的是非流式 `generate()`——此取消方法无效，因为 `_stream_response` 在非流式路径中始终为 None。

## 4. 代理影响

### 4.1 OpenAI SDK 默认 httpx 行为

```python
# core/ai_client.py:456 — generate() 非流式客户端创建
client = OpenAI(**kwargs_opts)
# kwargs_opts = dict(api_key=..., base_url=..., timeout=httpx.Timeout(120.0, connect=10.0))
```

OpenAI SDK 创建 `httpx.Client` 时**无显式 `http_client` 参数** → 走到 SDK 内部的默认 httpx 客户端创建。

### 4.2 httpx 默认对环境变量的行为

httpx.Client 的构造器默认参数 `trust_env=True`。当构建时没有传 `proxies`、`trust_env` 或自定义 `transport`：

- 若系统/用户设置了 `HTTP_PROXY` 环境变量 → 所有 HTTP 请求尝试走代理
- 若代理对 `127.0.0.1` 不做豁免 → `http://127.0.0.1:8080/v1/chat/completions` 可能被代理拦截

**当前代码没有对 127.0.0.1 显式豁免 proxy**——没有 `proxies=None`、没有 `trust_env=False`、没有 `http_client=httpx.Client(trust_env=False)`。

### 4.3 本地 base_url 使用 HTTP

```python
# core/ai_client.py:111
DEFAULT_LOCAL_BASE_URL = 'http://127.0.0.1:8080/v1'
```

走 HTTP（非 HTTPS），httpx 默认遵循 `HTTP_PROXY`。如果用户机器上配置了代理（如 `HTTP_PROXY=http://proxy.company.com:8080`），本地请求会被引导到代理。

## 5. 空数据首轮 — prompt_est_tokens=19

### 5.1 DIAG 证据

```
[DIAG] _run_multi_agent: backend=local, model=qwen3.5-9b, ctx=8192, prompt_est_tokens=19, ...
```

### 5.2 复现条件

`prompt_est_tokens=19` 来自 `_run_multi_agent` 中的 token 估算：

```python
# ui/ai_diagnosis.py:1477-1482
_prompt_est = _ai._estimate_tokens('') + _ai._estimate_tokens(user_input)
```

`_estimate_tokens('')` = 0。`_estimate_tokens(user_input)` = 19 → user_input 约 32 字符。

User input 来自：

```python
# ui/ai_diagnosis.py:1472
context_text = self._build_context_text(ctx)
user_input = f"请分析以下传感器数据:\n\n{context_text}\n\nCSV文件路径: {csv_path or '未指定'}"
```

**如果 `context_text` 短（无勾选 provider、无清洗、无传感器结果），`user_input` 就短**。19 tokens 的 user_input 加上 prompt 前缀不超过约 50 字符 → user 看到的 prompt 几乎只有一句"请分析以下传感器数据"。

### 5.3 追踪

```python
# ui/ai_diagnosis.py:1684-1697 — _build_context_text 可能返回几乎空文本
if not ctx or ctx.get("error"):
    return "当前无数据。"
...
if not ctx.get("has_data"):
    has_external = bool(self._external_files)
    if has_external:
        lines.append("注意：本次诊断使用外部（未经本软件处理）数据文件...")
    else:
        return "当前无数据。"       # ★ 返回仅此一句
```

**复现条件**：
1. 用户未加载数据文件 (`has_data=False`)
2. 没有勾选任何 provider（或 all is_available=False → summaries 为空 list）
3. 没有外部文件
4. → `context_text = "当前无数据。"`
5. → `user_input = "请分析以下传感器数据:\n\n当前无数据。\n\nCSV文件路径: 未指定"`
6. → `_estimate_tokens(user_input)` ≈ 19 tokens

空快照首轮不是本批改动的结果——`_build_context_text` 和 `_build_data_context` 的早期退出逻辑（has_data=False → 仅返回 provider_summaries + 外部文件检查）自建立以来自始至终如此。本批改动未触发此路径的变化。
