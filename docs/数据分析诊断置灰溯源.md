## 2. AnalysisProvider.is_available 读什么

**`core/data_providers.py:598-604`**：

```python
class AnalysisProvider(DataProvider):
    display_name = "数据分析"
    disabled_hint = "无结果 — 运行数据分析后可用"

    def is_available(self, main_win: Any) -> bool:
        sr = getattr(main_win, 'sensor_results', None)
        return bool(sr)
```

读取 `main_win.sensor_results`。若为 `None` 或 `{}` → `bool()` 返回 `False` → 复选框置灰 + 标注"(无结果 — 运行数据分析后可用)"。

**`main_win` 是 `DataProcessorWindow`**（`main.py:338`）。

## 4. 对比正常亮的项 — 为什么它们不被置灰

| Provider | 读哪个属性 | 谁写这个属性 | 写入时机 | 文件:行号 |
|----------|----------|------------|---------|-----------|
| **DataFileProvider** | `main_win.current_data` | `main.py` 文件加载函数 | 加载任何数据文件时 | `is_available: data_providers.py:131-133` |
| **CleaningProvider** | `cleaning_tab._cleaning_has_run` | `cleaning_tab.py` 清洗按钮 handler | 用户点"应用清洗"时 | `is_available: data_providers.py:528-532` |
| **CalibrationProvider** | `temp_page._phase_a_state` / `_phase_b_state` | `calibration_tab.py` 标定按钮 handler | 用户运行标定 Phase A/B 时 | `is_available: data_providers.py:271-279` |
| **AnalysisProvider** ❌ | `main_win.sensor_results` | FBG 路径: `main.py:798` 通用路径: **未找到** | FBG: `calculate_sensors()` 通用: **从不写** | `is_available: data_providers.py:602-604` |

**对比结论**：
- 前三个 provider 读的属性（`current_data` / `_cleaning_has_run` / `_phase_a_state`）都由**各自页面的操作 handler 直接写入主窗口或自身实例**，且写入与读取是同一属性。
- `AnalysisProvider` 读 `main_win.sensor_results`，但通用数据路径**只写 `analysis_tab_widget._sensor_results`，不写 `main_win.sensor_results`**。

## 5. 断点判定 — 属性名不匹配 (a) + 通用路径漏写主窗口 (b)

**断点类型**: **(a) provider 读错属性名** — 但更精确说是 **(b) 通用数据路径漏写 `main_win.sensor_results`**。

**证据链**：

| # | 证据 | 文件:行号 |
|---|------|-----------|
| 1 | `AnalysisProvider.is_available` 读 `main_win.sensor_results` | `data_providers.py:603` |
| 2 | `main_win.sensor_results` 初始化 `{}` | `main.py:349` |
| 3 | FBG 路径写了 `self.sensor_results = cleaned` | `main.py:768, 798` |
| 4 | 通用路径 `_push_annotation_sensor_results` **没写** `self.sensor_results` | `main.py:2668` — 只调了 `analysis_tab_widget.set_sensor_results(sensor_results)` |
| 5 | `analysis_tab_widget.set_sensor_results()` 只写 `self._sensor_results`（tab 本地属性），不碰 `main_win` | `analysis_tab.py:275-276` |
| 6 | `analysis_tab._get_sensor_results()` 读的是 `self.window().sensor_results`（即 `main_win.sensor_results`）— 通用数据路径下返回 `{}` | `analysis_tab.py:884-886` |

**但 analysis tab 的图表/统计为什么正常？** 因为图表不读 `main_win.sensor_results` — `analysis_tab.py:522` 和 `:656` 调用 `_get_sensor_results()` 但在此之前，`_on_analysis_refresh_requested()` 已经通过 `set_current_data` 给 tab 提供了 `analysis_df`；统计信息更多是从 `analysis_df` / `_current_plot_df` 计算的。只有在 FBG 模式下，`_get_sensor_results()` 返回非空 dict 时才会用于传感器列表。通用数据模式的传感器列表从 annotated_cols 构建 (`analysis_tab.py:929+`)。

**根因**：`_push_annotation_sensor_results`（`main.py:2662-2668`）漏写 `self.sensor_results = sensor_results`。FBG 路径 `calculate_sensors` 写了（`main.py:798`），通用路径没写。`AnalysisProvider.is_available` 读的是只有 FBG 路径才会设置的主窗口属性。
