## 4. 加载项目恢复范围 — restore() 回填哪些字段

### 4.1 Step 0: 重读源文件

```python
# py/calibration/project_config.py:354-368
if src_path and os.path.isfile(src_path):
    df, file_annot, meta = parse_enlight_file(src_path)
    tp._loaded_df = df
    tp._annotation_meta = meta
    tp._time_col_idx = 0
    tp.file_path_edit.setText(src_path)
else:
    tp._loaded_df = None
    file_annot = {}
```

**关键行为**: 加载项目后 `tp._annotation_dict` 尚未被 set — 它现在还是 `_load_and_parse` 时填充的值(或上一轮的旧值), 但 `restore()` 不会在此步骤 touch 它。`file_annot` 存为局部变量供下一步。

### 4.2 Step 1: 三层合并

```python
# py/calibration/project_config.py:370-383
profile_annot = t.get("annotation", {}) or {}     # ★ 从 JSON 读出
tp_dirty = getattr(tp, '_annotation_dirty', set()) or set()  # ★ 永远为 set() — 未持久化
tp_existing = dict(getattr(tp, '_annotation_dict', {}) or {})
# 以文件暗号为底
merged = dict(file_annot) if file_annot else {}
for col_name, profile_val in profile_annot.items():
    if col_name in tp_dirty:
        # 用户手动编辑过 → 锁定, 保持用户值
        if col_name in tp_existing:
            merged[col_name] = tp_existing[col_name]
    elif col_name not in merged or not merged.get(col_name):
        # 文件无该列暗号 → 用 profile 值
        merged[col_name] = profile_val
tp._annotation_dict = merged
```

**三层优先级**: `手改锁定` > `文件自带头` > `profile 存档值`

**缺口在此**: `tp_dirty` 永远为 `set()` — 因为 `_annotation_dirty` 没有随 `temperature` JSON 段持久化。它只在 `tp._phase_a_state["annotation_dirty"]` 中短暂存在 (下一个步骤才会 if 重建)。

后果: 如果 ENLIGHT 文件头自带了暗号 (比如旧版本文件有 `'W1'`, `'W2'` 等未格式化的占位文本), 这些会以 `file_annot` 形式进入 merged, 且因为 dirty 锁不存在, 文件占位会覆盖 profile 中用户手改的真值。

### 4.3 Step 5: 同步 _phase_a_state

```python
# py/calibration/project_config.py:438-446
tp._phase_a_state = {
    "annotation": dict(getattr(tp, '_annotation_dict', {})),
    "annotation_dirty": list(getattr(tp, '_annotation_dirty', set()) or set()),
    ...
}
```

这里从 `tp._annotation_dict`(现在已经是 merged) 取值写入 phase_a_state, 同时 `annotation_dirty` 取到的是 set() → 存为空列表。PhaseA 对话框打开时读取此 state, 但 dirty 为空 → 无列被锁定。

### 4.4 断点在"没存"还是"存了没恢复"

**断点在"存了, 但被文件重解析覆盖"**:

- `capture()` 确实存了 `tp._annotation_dict` → JSON 有值 ✅
- `restore()` Step 1 确实读了 JSON 值 → `profile_annot` 有值 ✅
- 但 `tp_dirty` 为空 → 无锁 → 如果文件重解析 (`file_annot`) 返回了任何非空值, 文件值优先于 profile 值
- 如果原 ENLIGHT 文件的注脚行中某些格是空的 → `file_annot` 中对应列为空 → `not merged.get(col_name)` 为 True → profile 值兜底填入 → **此时应正常**
- 如果原文件中有旧版本的注脚(如 `'W1'` 列名本身作为"暗号") → `file_annot["当前列名"] = "W1"` → `merged.get("当前列名")` = `"W1"` (truthy) → profile 值被跳过 → **文件旧值覆盖用户手改**

## 5. 分组依赖 — 暗号空 → 全单栅 → Phase B 空白

### 5.1 双栅判定的代码

```python
# ui/calibration_tab.py:112-131
def _group_annotations_by_prefix(data_cols: dict, df=None) -> dict:
    groups: dict[str, list[dict]] = {}
    for col_idx, name in data_cols.items():
        prefix = name.split('-')[0] if '-' in name else name   # ★ 'A1-W1' → 'A1'; 'W1' → 'W1'
        entry: dict = {"name": name}
        if df is not None and 0 <= col_idx < len(col_list):
            entry["col_name"] = col_list[col_idx]
        groups.setdefault(prefix, []).append(entry)
    return groups
```

双栅判定: 同 prefix 下 ≥2 个 entry → 双栅。如 `A1-W1, A1-W2` → prefix=`A1`, 2 entries → 双栅。

### 5.2 因果链

```
parse_enlight_file 返回的 annotation: 无有效暗号 (文件头无注脚)
  ↓
_annotation_dict = {} 或 {"W1":"", "W2":"", ...}
  ↓
PhaseA 对话框打开 → "当前暗号"列全为占位/空白
  ↓
data_cols_for_group: 仅含文件名作为"暗号"本身 (如 'W1') 
  或完全为空 (如果没有 '-' 且 isValid_annotation 拒绝)
  ↓
_group_annotations_by_prefix → 每个 prefix 只含 1 个 entry (如 'W1' 单独一组)
  ↓
"当前合法 0 个, 待填 12 个" → 12 组全判单栅
  ↓
Phase B coef_table 行: 循环 self._groups → 每个 prefix 只有 1 个 grating → 全跳过
  ↓
"无双栅传感器, 仅汇总温度系数"
```

### 5.3 确认

```python
# ui/calibration_tab.py:1686-1696 — Phase B coef_table 行判定
for pfx, gratings in self._groups.items():
    if len(gratings) < 2:               # ★ 判据
        continue
```

**证据**: `_groups` 每个 prefix 下若只有 1 个 grating → 跳过 → 表空。

### 6.2 向后兼容风险

新增字段 (如 `annotation_dirty`) → 旧项目 JSON 加载时不报错 (`from_dict` 取 `.get()` 带 default), 但值永远为默认值 (空 list)。这是 pyright-friendly 行为, 不存在硬崩溃。

**核心风险**: 不是缺字段导致旧文件无法 load — 是从旧文件 load 后, dirty 锁永远为空, 文件头旧暗号覆盖用户新暗号。

## 补证 (2026-06-24)

### 补 1: 合并逻辑逐行 — "文件胜出"的代码依据

```python
# py/calibration/project_config.py:370-385 — Step 1 全文
# Step 1: annotation — ★ 三层优先级合并 (手改 > 文件 > profile)
profile_annot = t.get("annotation", {}) or {}                # ① 从 JSON 读回用户暗号
tp_dirty = getattr(tp, '_annotation_dirty', set()) or set()   # ② ★ 永远为 set() — 见补 2
tp_existing = dict(getattr(tp, '_annotation_dict', {}) or {})
# 以文件暗号为底
merged = dict(file_annot) if file_annot else {}               # ③ 底 = 文件头暗号
for col_name, profile_val in profile_annot.items():           # ④ 遍历 JSON 中的用户暗号
    if col_name in tp_dirty:                                   # ⑤ ★ 从不为真 — dirty=set()
        # 用户手动编辑过 → 锁定, 保持用户值
        if col_name in tp_existing:
            merged[col_name] = tp_existing[col_name]
    elif col_name not in merged or not merged.get(col_name):   # ⑥ merged 该列无值/空 → profile 兜底
        # 文件无该列暗号 → 用 profile 值
        merged[col_name] = profile_val
    # else: 文件有非空暗号 → 保持文件值 (已在上面的 merged 中)  # ⑦ ★ 文件胜出
tp._annotation_dict = merged                                   # ⑧ 写入温度页
```

**执行路径**：③ `merged = file_annot` 以文件为底 → 对每列，⑤ dirty 锁失效 → 跳到⑥：如果文件该列有值 → `merged.get(col_name)` 为 truthy → 不满足 `not merged.get(col_name)` → ⑥ 不触发 → profile 值被跳过 → ⑦ 生效：**文件值保留，profile 值被覆盖**。

**"文件胜出"成立条件**：文件头该列的注脚非空（如 `'W1'`、`'Channel 1'` 等任何非空字符串）。ENLIGHT 文件头可能有出厂默认列标注——它们不是用户手写的合法暗号，但在合并中优先于用户真值。

### 补 3: "文件重解析"是否必要 — Step 0 的目的

Step 0 调用 `parse_enlight_file(src_path)` 返回三个值：

```python
# py/calibration/project_config.py:358
df, file_annot, meta = parse_enlight_file(src_path)
```

各自的消费点与必要性：

| 产物 | 写入位置 | 消费用途 | 是否必须 |
|------|---------|---------|---------|
| `df` | `tp._loaded_df` (line 359) | Phase A 暗号补填表 `_fill_table` 读列名；S_eff 回归读波长数据；Phase B 解耦读 dL 数组 | **是** — 无 DataFrame 则整个标定页不可用 |
| `meta` | `tp._annotation_meta` (line 360) | `_sync_info_label()` 显示文件格式标签 | 非必须 — 仅 UI 信息展示 |
| `file_annot` | 局部变量 → Step 1 合并 (line 375) | 作为 annotation 合并的底 | **否** — 暗号源 = profile JSON 已足够 |

```python
# py/calibration/project_config.py:275-306 — parse_enlight_file 的 docstring
"""统一 ENLIGHT / Hyperion 解析器 — 内容感知格式判别。
...
Returns:
    (df, annotation, meta)
      - df:         清洗后的数据 DataFrame，列名已去引号
      - annotation: {列名: 暗号字符串} 从引号包裹格提取
      - meta:       {format, header_idx, num_meta_skipped, num_numeric_cols, ...}
"""
```

`parse_enlight_file` 的目的**不包含**提供加载后所需的暗号映射——它的 annotation 返回的是**文件头注脚行的原始文本**，是出厂模板中的默认标注或空白。加载项目时，用户已保存的暗号在 project JSON 的 `temperature.annotation` 字段中。

**暗号被覆盖纯属误伤**：Step 0 必须重读文件以重建 `_loaded_df`（否则 Phase A/B 无法工作）。`file_annot` 是这步的伴生输出，并无独立需求。但它在 Step 1 中被当作合并的基底，导致其值优先于 profile JSON。若合并时将 profile 设为基底、文件仅作兜底，此误伤不存在。
