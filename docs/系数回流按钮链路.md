## 2. 数据搬运

### 2.1 从应变页读取

```python
# ui/calibration_tab.py:4210-4216
for s_name, cfg in self._strain_configs.items():
    mode = getattr(cfg, 'sensor_mode', 'single')
    ke = getattr(cfg, 'ke_results', {}) or {}     # ★ 从 StrainSubConfig 读
    if not ke:
        continue
    ke_dict = {str(k): float(v) for k, v in ke.items()}  # {"Ke1": 1.18, "Ke2": 0.95}
```

**读取源**: `self._strain_configs[s_name].ke_results` — StrainSubConfig dataclass 的字段，类型 `dict[str, float]`。

**门控 1**: 仅处理 `sensor_mode` 为 `"dual_working"` 或 `"dual_anchored"` 的传感器（`ui/calibration_tab.py:4223`）。

**门控 2**: 仅当 `self._has_temperature_data()` 返回 True 时才执行写入（`ui/calibration_tab.py:4225`）。该函数检查温度页 `_loaded_df` 非空且 `_phase_a_done = True`（`ui/calibration_tab.py:3203-3211`）。若温度标定未就绪，双栅 Ke 系数仅保存到 `ProjectConfig.strain`（不写 ke_table）。

### 2.2 写入温度页


## 3. 写入/读取结构对账

### 3.1 写入侧 (`_apply_coefficients`)

```python
# ui/calibration_tab.py:4216
ke_dict = {str(k): float(v) for k, v in ke.items()}
# 结果: {"Ke1": 1.18, "Ke2": 0.95}   类型: dict[str, float]

# ui/calibration_tab.py:4235
pb_state["ke_table"][s_name] = ke_dict
# 结果: ke_table["A1"] = {"Ke1": 1.18, "Ke2": 0.95}
```

### 3.2 读取侧 — CalibrationProvider.get_summary()

```python
# core/data_providers.py:291
ke_table = _normalize_coeffs(pb.get('ke_table', {}))
```

`_normalize_coeffs` 的处理：
```python
# core/data_providers.py:823-826
elif isinstance(v, dict):
    out[s] = {
        "Ke1": float(v.get("Ke1", float("nan"))),
        "Ke2": float(v.get("Ke2", float("nan"))),

```

**键名对账**：

| 项目 | 写入键名 | 读取键名 | 一致？ |
|------|---------|---------|--------|
| 传感器级 | `ke_table["A1"]` | `ke_table["A1"]` | ✅ |
| 系数键 | `"Ke1"`, `"Ke2"` | `"Ke1"`, `"Ke2"` | ✅ |
| 系数值类型 | `float` | 经 `float()` 再转 | ✅ |
| 传感器名 | str (如 "A1") | str | ✅ |

**结论：写入数据结构与 `_normalize_coeffs` 期望的读取结构完全一致。不是"传过去了但读不出来"的问题。**

### 3.3 读取侧 — `_get_strain_ke()` 的优先拦截

但 CalibrationProvider 在直接读 ke_table 之前，有**另一条优先路径**：

```python
# core/data_providers.py:358-370
strain_ke = _get_strain_ke(main_win, s_name) if main_win else None
if strain_ke:                                    # ★ 优先使用 strain_ke
    ke1_s = f"{float(strain_ke['Ke1']):.4f}"
    ke2_s = f"{float(strain_ke['Ke2']):.4f}"
else:
    ke = ke_table.get(s_name, {}) if ke_table else {}  # ★ 仅 strain_ke 为空时回落
    ...
```

### 3.4 `_get_strain_ke` 内部路径分析

```python
# core/data_providers.py:849-863
sp = getattr(ct, 'strain_page', None)

# 路径 1: sp._phase_b_state ← StrainCalibrationPage 无此属性 — 永不触发
if sp and hasattr(sp, '_phase_b_state'):
    sb = sp._phase_b_state or {}
    strain_data = sb.get(sensor, {})
    if isinstance(strain_data, dict):
        ke = strain_data.get('ke_results', {})
        if ke:
            return {"Ke1": float(ke.get("Ke1", 0)), "Ke2": float(ke.get("Ke2", 0))}

# 路径 2: sp._strain_configs ← 唯一可到达路径
if sp and hasattr(sp, '_strain_configs'):
    sc = sp._strain_configs or {}
    for _, cfg in sc.items():
        ke = getattr(cfg, 'ke_results', None)       # ★ 返回 dict: {"Ke1": 1.18, "Ke2": 0.95}
        if ke and getattr(cfg, 'sensor_name', '') == sensor:
            return {
                "Ke1": float(getattr(ke, 'Ke1', 0)),   # ★ BUG: ke 是 dict, 不是 object
                "Ke2": float(getattr(ke, 'Ke2', 0)),   # ★ getattr(dict, 'Ke1', 0) → 0
            }
```

**第 862 行的 bug**: `ke` 是 `cfg.ke_results` 返回的 Python `dict`（如 `{"Ke1": 1.18, "Ke2": 0.95}`）。`getattr(ke, 'Ke1', 0)` 对 dict 执行：dict 没有名为 `'Ke1'` 的属性 → 返回默认值 `0`。

**结果**: `_get_strain_ke` 返回 `{"Ke1": 0.0, "Ke2": 0.0}`。

**后果**:
1. `strain_ke` = `{"Ke1": 0.0, "Ke2": 0.0}` — **truthy**
2. `if strain_ke:` 条件成立
3. CalibrationProvider 用 `strain_ke` 的值输出 `Ke1/Ke2=0.0000/0.0000`
4. **ke_table 的真实值 (1.18 / 0.95) 永远不可达** — else 分支被跳过

## 4. is_available 影响

### 4.1 is_available 判定逻辑

```python
# core/data_providers.py:269-273
pa = getattr(tp, '_phase_a_state', {}) or {}
pb = getattr(tp, '_phase_b_state', {}) or {}
has_a = bool(pa.get('seff_result'))
has_b = bool(pb.get('decoupling_results') or pb.get('compensation'))
return has_a or has_b
```

### 4.2 ke_table 不在判据中

`ke_table` 不参与 `is_available()` 的任何分支：
- `has_a` 只看 `seff_result`
- `has_b` 只看 `decoupling_results` 或 `compensation`

### 4.3 按钮写入后的三种 is_available 状态

| 场景 | seff_result | decoupling | compensation | is_available | 标定摘要 |
|------|------------|------------|-------------|-------------|---------|
| 仅点按钮，无 Phase A/B | None/空 | {} | {} | **False** | 不注入快照 |
| Phase A 已做 + 按钮 | 非空 dict | {} | {} | **True** (from has_a) | 输出但 Ke 被 `_get_strain_ke` 置 0 |
| Phase A + Phase B + 按钮 | 非空 dict | 非空 | 非空 | **True** | 正常输出 Ke |

**关键场景**: 用户完成温度 Phase A（有 S_eff）→ 应变标定完成后点按钮（写 ke_table）→ 但 Phase B **未做**（无 decoupling/compensation）。

此时 `has_a = True`, `has_b = False` → `is_available = True` → CalibrationProvider 被调用 → `get_summary` 走 `sensor_ids = ke_table 的 keys`（非空）→ 进入 per-sensor 循环 → `_get_strain_ke` 返回 `{0.0, 0.0}` → 输出 `Ke1/Ke2=0.0000/0.0000`。

## 5. 本次诊断"系数缺失"成因判断

### 5.1 用户侧已知条件

- 真机 Ke 表: A1 Ke1=1.18 等 ✓
- 温度 S_eff 已标定 ✓
- 应变 Ke 已拟合完成 ✓
- 按钮"应用全部系数"已点击 ✓

### 5.2 推断的完整故障链

```
用户完成应变标定 → A1 Ke1=1.18 写入 _strain_configs
       ↓
用户点击「应用全部系数到温度标定」
       ↓
_write_to_ke_table: tp._phase_b_state["ke_table"]["A1"] = {"Ke1": 1.18, "Ke2": 0.95}  ✅ 写入成功
       ↓
用户打开 AI 诊断 → 勾选「传感器标定」→ 多智能体启动
       ↓
is_available(): seff_result 存在 → has_a = True → is_available = True  ✅
       ↓
CalibrationProvider.get_summary(): sensor_ids = {"A1", "A2", ...}  ✅ 有数据
       ↓
进入 per-sensor 循环 → 调用 _get_strain_ke(main_win, "A1")
       ↓
_get_strain_ke: StrainCalibrationPage 无 _phase_b_state → 路径 1 跳过
       ↓
_get_strain_ke 路径 2: sp._strain_configs["A1"].ke_results → {"Ke1": 1.18, "Ke2": 0.95}  ✅ 读到
       ↓
返回: getattr(ke, 'Ke1', 0) → ke 是 dict → 无 'Ke1' 属性 → 返回 0  ❌
       ↓
_get_strain_ke 返回 {"Ke1": 0.0, "Ke2": 0.0}  ← truthy
       ↓
CalibrationProvider: if strain_ke → True → 输出 Ke1/Ke2=0.0000/0.0000  ❌
       ↓
LLM 模型看到: "Ke1/Ke2=0.0000/0.0000" → 判断系数缺失
```

### 5.3 根因

`core/data_providers.py:862` — `getattr(ke, 'Ke1', 0)` 对 dict 使用 `getattr` 而非 `.get()`。

`cfg.ke_results` 返回 Python dict `{"Ke1": 1.18, "Ke2": 0.95}`。`getattr(a_dict, 'Ke1', default)` 永远返回 default (0)，因为 dict 对象没有 'Ke1' 属性。

### 5.4 对比：同样的 bug 在路径 1 不存在

路径 1 (line 854-856) 使用 `ke.get("Ke1", 0)` — 正确的 dict 方法。但路径 1 因 `sp._phase_b_state` 不存在而永不触发。

### 5.5 次级因素

即使没有 `_get_strain_ke` 这个 bug，还有一个设计缺陷：`_get_strain_ke` 的返回值优先于 ke_table，但前者的传感器名匹配逻辑 (`getattr(cfg, 'sensor_name', '') == sensor`) 可能与 ke_table 的 key 脱节（应变 `_strain_configs` 的 key 依赖暗号推断，而温度 `ke_table` 的 key 依赖 Phase B 对话框的 coef_table）。
