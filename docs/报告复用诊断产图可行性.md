## 1. gen_charts_from_bundle 的输入

### 1.1 函数签名

`core/chart_bundle.py:289-290`
```python
def gen_charts_from_bundle(cd: dict, manifest, charts_dir: str,
                            warnings: list[str]) -> None:
```

输入四个参数：
- `cd: dict` — ChartBundle 序列化后的字典（即 `bundle.to_dict()` 产物）
- `manifest` — `FigureManifest` 实例（`core/report_charts.py`），收集图元供后续 Word/PPT 装配
- `charts_dir: str` — PNG 落盘目录
- `warnings: list[str]` — 出图失败的警告文本，调用方最终展示给用户

### 1.2 读取的字段 → 产出的图（一一对应）

全部位于 `core/chart_bundle.py:307-397`。

| 输入字段 | 必需要素 | 产出 PNG | 缺字段时行为 | 代码行 |
|----------|---------|----------|-------------|--------|
| `calib_ref` + `calib_measured` | 两者均非空 list | `calib_linearity.png` | `_skipped.append("calib_lin(no calib_ref/measured)")` | 307-324 |
| `calib_sensor`, `calib_unit`, `calib_r2`, `calib_slope` | (元数据，不产出单独图) | — | 不影响出图，仅影响 manifest label | 317-319 |
| `time_h` + `series` | 两者均非空 | `ts_cleaning.png` | `_skipped.append("ts_cleaning(no time_h/series)")` | 326-340 |
| `cleaned` | 可选 | ts_cleaning 上的清洗叠加层 | 缺 → `cleaned=None`，仍出图但无清洗对比 | 327,331 |
| `compare_time_h` + `compare_sources` | 两者均非空 | `compare_ol.png` | `_skipped.append("compare_ol(no compare_time_h/sources)")` | 342-354 |
| `compare_pairs` | 非空 list | `corr_{a}_{b}.png`（每个 pair 一张） | `_skipped.append("corr_scatter(no compare_pairs)")` | 356-375 |
| `hyst_sensors` | 非空 list，每项含 `{name, T_abs, eps}` | `hyst_{name}.png`（每个传感器一张） | `_skipped.append("hyst_loop(no hyst_sensors)")` | 377-395 |

**关键设计**：空字段不崩，只 skip + 记 warning。调用方永远拿到一个 `manifest` 对象，其中有几张图取决于输入数据有多完整。

### 1.3 ChartBundle 完整字段定义

`core/chart_bundle.py:16-51`
```python
@dataclass
class ChartBundle:
    time_h: list[float]           # 时间轴 (h), 已抽稀
    series: dict[str, list[float]] # {通道名: 值数组}
    cleaned: dict[str, list[float]] # {通道名: 清洗后数组}
    time_downsample: int = 1

    compare_time_h: list[float]
    compare_sources: dict[str, list[float]]
    compare_pairs: list[dict]     # [{device_a, device_b, corr, rmse, mae}]

    hyst_sensors: list[dict]      # [{name, T_abs, eps}]

    calib_ref: list[float]
    calib_measured: list[float]
    calib_sensor: str = ""
    calib_unit: str = "με"
    calib_r2: float = 0.0
    calib_slope: float = 0.0

    grade_table_md: str = ""      # 传感器分级表 (markdown)
    anomaly_table_md: str = ""    # 异常统计表
    ke_table_md: str = ""         # 应变 Ke 汇总表
    decoupling_table_md: str = "" # 温度 B 解耦标量表
```

## 2. 报告路径手里有什么 — record.chart_data 字段

### 2.1 报告生成入口

`main.py:1281-1350`（报告 worker 的 `_build_and_save` 函数）

报告生成时：
1. `config` 由 `report_workbench.get_config()` 构建（`ui/report_workbench.py:120-133`）
2. `config['_diagnosis_record']` = 用户点击「从已存诊断加载」后加载的完整诊断 JSON
3. 该 JSON 由 `ui/ai_diagnosis.py:1119-1192`（`_build_diagnosis_record`）在诊断完成时构建并保存

### 2.2 record 结构（schema_version 1.2）

`ui/ai_diagnosis.py:1128-1192`
```python
rec = {
    "schema_version": "1.2",
    "timestamp": "2026-...",
    "backend": ..., "model": ...,
    "selected_sources": [...],
    "data_source_snapshot": [...],
    "kb_hits": [...],
    "ai_diagnosis": {"diagnosis_json": ..., "diagnosis_raw": ...},
    "multi_agent": {"chief_structured": ..., ...},
    "chart_data": {...},   # ← ChartBundle.to_dict() 产物
}
```

### 2.3 chart_data 的来源 — ChartBundle.from_providers()

`core/chart_bundle.py:54-243`

`chart_data` = `ChartBundle.from_providers(main_win).to_dict()`。**这是诊断保存时刻的实时 UI 状态快照。**

| chart_data 字段 | 数据来源 | `from_providers` 是否填充 |
|----------------|---------|--------------------------|
| `time_h` | `analysis_tab_widget._current_data`（前 5 数值列，抽稀到 ~200 点） | ✅ |
| `series` | 同上 | ✅ |
| `cleaned` | — | ❌ **从未填充** |
| `time_downsample` | 抽稀步长 | ✅ |
| `compare_time_h` | `compare_tab_widget._last_comparison` | ✅（有对比时） |
| `compare_sources` | 同上 | ✅（有对比时） |
| `compare_pairs` | 同上 | ✅（有对比时） |
| `hyst_sensors` | — | ❌ **从未填充** |
| `calib_ref` | `strain_page._strain_configs[].readings` → ε_ref = disp / gauge × 1e6 | ✅（有应变标定读数时） |
| `calib_measured` | 同上，乘 avg Ke | ✅ |
| `calib_sensor` | 同上 | ✅ |
| `grade_table_md` | `temp_page._phase_b_state.compensation` | ✅（有补偿数据时） |
| `decoupling_table_md` | `temp_page._phase_b_state.decoupling_results` | ✅（有解耦数据时） |
| `ke_table_md` | `strain_page._strain_configs` | ✅（有应变标定时） |
| `anomaly_table_md` | `cleaning_tab_widget._anomaly_info` | ✅（有异常数据时） |

### 2.4 关键缺口

**`from_providers` 不填充 `hyst_sensors`。** 这意味着任何通过 `from_providers` 构建的 ChartBundle —— 无论是实时诊断保存还是报告生成时重建 —— 其 `hyst_sensors` 永远为空列表。证据：

- 代码检查：`chart_bundle.py:54-243` 全文无 `bundle.hyst_sensors = ...` 或 `.hyst_sensors.append(...)`
- 测试明确断言：`tests/test_chart_bundle_from_providers.py:311` — `assert bundle.hyst_sensors == []`

**同理 `cleaned` 也从不填充。** 不影响出图（ts_cleaning 可退化），但丢失清洗叠加层。

## 3. 诊断路径 vs 报告路径 — 对比

### 3.1 诊断保存路径（完整图集）

`ui/ai_diagnosis.py:1300-1305`
```python
from core.chart_bundle import gen_charts_from_diagnosis
gen_charts_from_diagnosis(rec, manifest, img_dir, wrn)
```

`gen_charts_from_diagnosis`（`core/chart_bundle.py:481-534`）：
1. 先取 `rec['chart_data']` → 非空则调 `gen_charts_from_bundle(cd, ...)` → 产全图集
2. 若 `chart_data` 为空（v1.0/v1.1 老 record）→ 降级到 `statistics` → 只产一张 `diag_metric_bar.png`

此路径有 record 的完整 `chart_data`，**但同样没有 `hyst_sensors`**（因为 chart_data 来自 `from_providers`）。

### 3.2 报告生成路径（残缺图集）

`main.py:1288-1303`
```python
manifest = FigureManifest()

# 1a. 实时 provider 取数
_generate_charts_from_providers(
    self, manifest, charts_dir, _report_warnings,
)

# 1b. 降级(诊断快照): provider 全不可用 → 从诊断记录取
diag_rec = config.get('_diagnosis_record')
if manifest.count == 0 and diag_rec:
    from core.chart_bundle import gen_charts_from_diagnosis
    gen_charts_from_diagnosis(
        diag_rec, manifest, charts_dir, _report_warnings,
    )
```

**步骤 1a**：`_generate_charts_from_providers`（`main.py:113-146`）→ 遍历 `get_all_providers()` → 每个 provider 调 `_gen_charts_for`（`main.py:150-255`）：

| Provider | `is_available` 条件 | `_gen_charts_for` 产出 |
|----------|---------------------|----------------------|
| `DataFileProvider` | 无对应 handler（_gen_charts_for 无此分支） | 无 |
| `CleaningProvider` | `cleaning_tab_widget._cleaning_has_run == True` | `cleaning_timeseries.png`（raw data only，无 cleaned 叠加） |
| `AnalysisProvider` | `analysis_tab_widget._current_data is not None` | **无**（Batch A 已删除 metric_bar/dist_box/grade_bar，直接 `return`，`main.py:221-223`） |
| `CompareProvider` | `compare_tab_widget._last_comparison` 非空 | `compare_overlay.png` + 相关散点图 |
| `CalibrationProvider` | `temp_page._phase_a_state` 或 `_phase_b_state` 非空 | **仅迟滞回线**（`main.py:236-251`），**不产 calib_lin** |
| `ExternalDataProvider` | 无对应 handler | 无 |

**步骤 1b**：仅当 `manifest.count == 0`（即 provider 全不可用）时才走诊断快照降级。只要有一个 provider 产了图（最常见：CleaningProvider 产 `cleaning_timeseries.png`），`manifest.count >= 1`，降级**永不触发**。

### 3.3 两条路的图集对比

| 图 | `gen_charts_from_bundle` (诊断路径) | 报告 provider 路径 | 报告降级路径 |
|----|-----------------------------------|-------------------|-------------|
| `calib_linearity.png` | ✅（需 calib_ref + calib_measured） | ❌ | ✅（同诊断） |
| `ts_cleaning.png` | ✅（需 time_h + series） | ✅（CleaningProvider，无 cleaned 叠加） | ✅（同诊断） |
| `compare_ol.png` | ✅（需 compare_time_h + compare_sources） | ✅（CompareProvider） | ✅（同诊断） |
| `corr_*.png` | ✅（需 compare_pairs） | ✅（CompareProvider） | ✅（同诊断） |
| `hyst_*.png` | ✅（需 hyst_sensors） | ✅（CalibrationProvider，直接读 `_phase_b_state['sensors']`） | ❌（chart_data 无 hyst_sensors） |
| `diag_metric_bar.png` | ❌（Batch A 已删） | ❌ | ✅（仅 v1.0/v1.1 降级） |

**根因确认**（已在 `docs/calib_lin图丢失溯源.md` 记录）：
- 报告路径走 provider → CalibrationProvider 不画 calib_lin → calib_lin 丢失
- 报告降级路径有能力产 calib_lin（通过 `gen_charts_from_bundle`），但因 `manifest.count >= 1` 永不被触发
- 降级路径自身也有缺口：`hyst_sensors` 不在 chart_data 中 → 降级也产不出迟滞回线

## 4. 老 record 兼容性

### 4.1 schema_version 演进

| 版本 | chart_data | 降级行为 | 记录位置 |
|------|-----------|---------|---------|
| 1.0 | 无 | `gen_charts_from_diagnosis` → 取 `statistics` → 产 `diag_metric_bar.png` | `test_report_diagnosis.py:8-56` |
| 1.1 | 无 | 同上 | `test_report_diagnosis.py:57-69` |
| 1.2 | 有（`ChartBundle.to_dict()`） | `gen_charts_from_diagnosis` → `gen_charts_from_bundle` → 全图集 | `ui/ai_diagnosis.py:1129` |

### 4.2 兼容性判断

`gen_charts_from_diagnosis`（`core/chart_bundle.py:481-534`）已做好兼容：
```
chart_data 非空 → gen_charts_from_bundle（v1.2 路径）
chart_data 空   → 降级 statistics → diag_metric_bar.png（v1.0/v1.1 老路径）
```

`from_diagnosis_record`（`core/chart_bundle.py:246-249`）用 `__dataclass_fields__` 白名单过滤：
```python
return cls(**{k: v for k, v in cd.items() if k in cls.__dataclass_fields__})
```
→ 老 record 即使含未知字段也不会崩；新字段缺省走 dataclass default。

### 4.3 旧 record 缺字段时的具体表现

| 缺失字段 | `gen_charts_from_bundle` 行为 | 影响 |
|---------|------------------------------|------|
| `chart_data` 整体缺失 | 走 statistics 降级 → 仅 `diag_metric_bar.png` | 丢全部图，只剩一根柱子 |
| `calib_ref` / `calib_measured` | `_skipped.append("calib_lin(no calib_ref/measured)")` | 丢标定线性度图 |
| `time_h` / `series` | `_skipped.append("ts_cleaning(no time_h/series)")` | 丢清洗时序图 |
| `compare_time_h` / `compare_sources` | `_skipped.append("compare_ol(no compare_time_h/sources)")` | 丢多源对比图 |
| `compare_pairs` | `_skipped.append("corr_scatter(no compare_pairs)")` | 丢相关散点图 |
| `hyst_sensors` | `_skipped.append("hyst_loop(no hyst_sensors)")` | 丢全部迟滞回线 |
| `cleaned` | `cleaned=None` → ts_cleaning 无清洗叠加层 | 功能降级，仍出图 |
| `grade_table_md` 等四表 | `gen_markdown_tables_from_bundle` 跳过空表 | 附表缺对应表 |

### 4.4 真机旧 record 风险评估

以 6/20 的旧 record 为例：
- 若 schema_version = 1.2 且 `chart_data` 含 `calib_ref` → `gen_charts_from_bundle` 可产 calib_lin
- 若 schema_version = 1.1 → 降级到 statistics → 只剩 `diag_metric_bar.png`
- **所有版本的 record 的 `chart_data.hyst_sensors` 都为空**（因为 `from_providers` 不填充）→ 降级路径产不出迟滞回线

## 5. 改法落点评估

### 5.1 当前代码结构

报告图生成在 `main.py:1282-1350`，分两步：

**步骤 1**（`main.py:1282-1303`）：真图生成
```python
# 1a. 实时 provider 取数
_generate_charts_from_providers(self, manifest, charts_dir, _report_warnings)

# 1b. 降级(诊断快照): provider 全不可用 → 从诊断记录取
diag_rec = config.get('_diagnosis_record')
if manifest.count == 0 and diag_rec:
    gen_charts_from_diagnosis(diag_rec, manifest, charts_dir, _report_warnings)
```

**步骤 2b**（`main.py:1327-1349`）：四表注入
```python
bundle = ChartBundle.from_providers(self)    # ← 第二次调 from_providers
cd = bundle.to_dict()
four_tables = extract_four_tables(cd)         # → 四张 markdown 表
```

### 5.2 改动选项

#### 选项 A：在 1a 之前先尝试 bundle（优先 bundle，provider 兜底）

```
diag_rec = config.get('_diagnosis_record')
if diag_rec and diag_rec.get('chart_data'):
    gen_charts_from_diagnosis(diag_rec, manifest, charts_dir, warnings)
else:
    _generate_charts_from_providers(self, manifest, charts_dir, warnings)
    if manifest.count == 0 and diag_rec:
        gen_charts_from_diagnosis(diag_rec, manifest, charts_dir, warnings)
```

- ✅ 逻辑最简：record 有 chart_data → 直接用，不走 provider
- ✅ 消除 `manifest.count == 0` 死逻辑
- ❌ `hyst_sensors` 缺口仍在（chart_data 不含此字段）→ 迟滞回线丢失
- ❌ 若 record 的 chart_data 为空但 provider 有迟滞数据，会损失 provider 路径的迟滞图

#### 选项 B：合并两路（bundle 为主 + provider 补 hyst）

```
# 1. bundle 出主力图集
if diag_rec:
    gen_charts_from_diagnosis(diag_rec, manifest, charts_dir, warnings)

# 2. provider 补 bundle 没有的图（hyst 回线）
#    只跑 CalibrationProvider 的 hyst 部分
```

- ✅ calib_lin + ts_cleaning + compare + hyst 齐全
- ❌ 双路维护：bundle 产一批 + provider 补另一批，未来新增图类型需评估归哪路
- ❌ 改动范围更大（需拆分 `_gen_charts_for` 的 CalibrationProvider 处理器）

#### 选项 C：修 `from_providers` 填 `hyst_sensors`（补数据源，不动流程）

在 `ChartBundle.from_providers`（`core/chart_bundle.py:54-243`）中增加：
```python
# 从 _phase_b_state['sensors'] 填 hyst_sensors
if tp:
    pb = getattr(tp, '_phase_b_state', {}) or {}
    sensors = pb.get('sensors') or {}
    for s_name, sd in sensors.items():
        bundle.hyst_sensors.append({
            'name': s_name,
            'T_abs': sd.get('T_abs', []),
            'eps': sd.get('eps_orig', sd.get('eps_corr', [])),
        })
```

然后选项 A 的 bundle-first 策略即可生效，不再丢迟滞图。

- ✅ 治本：chart_data 从此包含 hyst_sensors
- ✅ 不影响现有 provider 路径
- ⚠️ 新保存的 record 才受益；已存旧 record 的 chart_data 仍无 hyst_sensors
- ⚠️ 需评估 `T_abs`/`eps_orig` 数组大小（~10 万点）— `to_dict()` 序列化体积

#### 选项 D：保持两步但修复降级触发条件

不改架构，只修 `main.py:1299` 的条件：
```python
# 旧: if manifest.count == 0 and diag_rec:
# 新: if diag_rec:
if diag_rec:
    gen_charts_from_diagnosis(diag_rec, manifest, charts_dir, _report_warnings)
```

- ✅ 最小改动
- ❌ bundle 和 provider 产重复图（ts_cleaning × 2、compare × 2）
- ❌ manifest 可能重复添加同名图（FigureManifest 需检查去重逻辑）
- ❌ `hyst_sensors` 缺口仍在

### 5.3 步骤 2b（四表注入）的落点

`main.py:1327-1349` 当前：
```python
bundle = ChartBundle.from_providers(self)   # 第三次调 from_providers
cd = bundle.to_dict()
four_tables = extract_four_tables(cd)
```

若报告已加载 `_diagnosis_record`，可改为：
```python
cd = (config.get('_diagnosis_record') or {}).get('chart_data', {}) or {}
if not cd:
    bundle = ChartBundle.from_providers(self)
    cd = bundle.to_dict()
four_tables = extract_four_tables(cd)
```

- ✅ 有 record 时免调 `from_providers`（减少对实时 UI 状态的依赖）
- ✅ 老 record 无 chart_data → 自动降级到 `from_providers`
- ⚠️ 若 record 的 chart_data 四表为空但实时 UI 有四表数据 → 丢表；概率低（诊断保存时四表通常已填充）

### 5.4 改动范围汇总

| 文件 | 改动点 | 行号 |
|------|-------|------|
| `core/chart_bundle.py` | `from_providers` 增加 `hyst_sensors` 填充 | ~238（`return bundle` 之前） |
| `main.py` | 步骤 1a/1b 改为 bundle-first | 1292-1303 |
| `main.py` | 步骤 2b 改为优先用 record 的 chart_data | 1329-1331 |

### 5.5 关键缺口清单

| # | 缺口 | 影响 | 是否阻塞 |
|---|------|------|---------|
| 1 | `from_providers` 不填 `hyst_sensors` | chart_data 永无迟滞数据 → `gen_charts_from_bundle` 不产迟滞回线 | **阻塞** — 需先补 `from_providers` 或合并两路 |
| 2 | `from_providers` 不填 `cleaned` | ts_cleaning 无清洗叠加层 | 非阻塞（ts_cleaning 仍可出图，只是少一条曲线） |
| 3 | 旧 record (v1.0/v1.1) 无 `chart_data` | 降级到 statistics → 只剩 diag_metric_bar | 非阻塞（v1.2 已上线，存量 v1.0/v1.1 少） |
| 4 | 旧 record (v1.2) 的 `chart_data.hyst_sensors` 为空 | 即使切到 bundle 路径，已有 record 也产不出迟滞图 | 非阻塞（重新诊断+保存后修复） |
| 5 | 报告生成时 `from_providers` 依赖实时 UI 状态 | 若 UI 数据已清（如切换项目后），四表为空 | 非阻塞（步骤 2b 可改用 record chart_data） |
