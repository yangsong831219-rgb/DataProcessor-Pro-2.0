## 2. Word 插图机制 — 有桥但依赖 LLM 写出「图N」

### 注入流程


### `_inject_figures_by_reference` — `main.py:258-335`

**完整逻辑**：

1. 打开已构建的 docx，收集所有段落文本 (`line 273`)
2. 正则扫描 `图(\d+)`，建立 `fig_no → 首次引用段落索引` 映射 (`line 284-293`)
3. 从后往前插入 PNG + 图题段落到引用段落之后 (`line 296-314`)
4. **未被引用的图 → 追加"图表附录"节** (`line 317-330`)
5. 引用不存在的图N → 警告 (`line 291-293`)

**孤儿判定** (`main.py:317-330`)：

```python

if unreferenced:
```

### 断点

LLM 拿到了 `charts_context`（"图1: 标定线性度…"），但 LLM 写正文时没写 `图1` 这种引用 → 扫描器找不到 → 图变孤儿 → 追加到末尾附录。**桥存在（图号注入 prompt → LLM 引用 → 后处理扫描），但链的第二环（LLM 写出引用）不保证发生。** 这是 LLM 行为层面的断点，不是代码缺失。

## 3. PPT 插图机制 — 两条独立路都不通

### 路径 1：PPT 构建器自带的 `[INSERT_IMAGE]` 标签

`ppt_builder.py:147-169` — `_add_content_slide` 解析 slide bullet 中的 `[INSERT_IMAGE: filename]`：


`_try_insert_slide_image` (`ppt_builder.py:195-212`) — **查找路径有误**：


`project_dir` 值 — `main.py:1207`：


### 路径 2：`_inject_figures_by_reference` (图N 引用扫描)

## 4. 图文关联的桥 — 三段链，Word 通两节，PPT 全断

### Word 路径的四段链

```
① PNG 生成 (gen_charts_from_bundle / _gen_charts_for)
   → PNG 落盘到 报告/charts/
   → manifest.add(fig_id, title, caption, png_path)     ✅

② LLM 感知 (charts_context → SECTION_PROMPT_WORD)
   → manifest.to_llm_context() → "图1: 标题; 图2: ..."
   → SECTION_PROMPT_WORD chart_instruction ← 告诉 LLM 可引用图几
   → report_engine.py:645-652                             ✅ 传入

③ LLM 写出引用
   → LLM 在 markdown 正文中写 "如图1所示" / "(图2)"
   → 依赖 LLM 行为 — 可能写、可能不写               ⚠️ 不可靠

④ 后处理扫描注入 (_inject_figures_by_reference)
   → 正则扫描 docx 段落 r'图(\d+)'
   → 匹配 manifest → 插入 PNG + caption
   → 未引用 → 图表附录
   → main.py:258-335                                      ✅ (仅 .docx)
```

**Word 问题**: 链③ LLM 不写 `图N` → 图全变孤儿 → 堆附录末尾。

### PPT 路径的三段残桩

```
① PNG 生成 → 同 Word → PNG 有、manifest 有             ✅

② LLM 感知
   → charts_context NOT passed to _generate_ppt_report   ❌ 断
   → SECTION_PROMPT_PPT 无 chart_instruction 占位符      ❌ 断
   → LLM 不知有图可用

③ 输出后处理 (_inject_figures_by_reference)
   → Document(pptx_path) → python-docx 不读 pptx         ❌ 断

④ PPT 自带插图 (_try_insert_slide_image)
   → 查找 project_dir + filename → PNG 存在 charts/ 子目录
   → 路径拼接错误 — project_dir 不是 charts/             ❌ 断
```

**PPT 问题**: **①右侧全断** — prompt 不告 LLM 有图、后处理不扫 pptx、自带插图路径找不到 PNG。

## 5. chart_data / record 里的图引用

### chart_data 字段

`ai_diagnosis.py:1156-1173` — `rec["chart_data"] = bundle.to_dict()`：

`ChartBundle.to_dict()` 序列化 `dataclasses.asdict(self)` — 包含：`time_h`, `series`, `cleaned`, `calib_ref`, `calib_measured`, `hyst_sensors`, `compare_*`, 及四个 `*_table_md`。

**不包含**: 图的路径、manifest 条目、图号映射。这些都是报告生成时实时构建的 transient 对象（`FigureManifest`），不持久化到诊断记录。

### 无持久化图引用

**chart_data 是"数据束"，不是"图清单"**。它的作用是 `gen_charts_from_diagnosis` 重新出图 → 重新构建 manifest。但 manifest 本身不写入 record（不出现在 JSON 中）。下次报告生成时从诊断记录重新 `gen_charts_from_diagnosis` 产生的 manifest 是新的 transient 对象。

### LLM 提示中的 charts_context

`main.py:1259` — `charts_context = manifest.to_llm_context(max_chars=600)` — 这个字符串最多 600 字符，仅注入到 `SECTION_PROMPT_WORD`，不写入任何持久化存储。它是报告生成的临时产物。
