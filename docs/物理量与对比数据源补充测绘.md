## A：光纤公式配置模块 / 物理量计算

### 1. 公式模块定位

**核心计算函数**: `core/models.py:248-363` — `SensorSystem.calculate(df, fbg_columns)`。

输入: 原始波长 DataFrame（含 `w1..w12` 等波长列）。  
输出: `Dict[str, List[Optional[float]]]` — `{sensor_id: [物理量序列, ...]}`。

计算链 (`models.py:337-361`):

```python
for sensor in self.sensors:                               # 遍历所有已配置传感器
    if sensor.sensor_type == 'decoupling':                 # 解耦传感器
        strain_r, temp_r = self._evaluate_decoupling(...)  # → 应变(με) + 温度(°C)
        results[f'{sensor.id}_应变(με)'] = strain_r
        results[f'{sensor.id}_温度(°C)'] = temp_r
    else:                                                  # 普通传感器
        result = self._evaluate_sensor_formula(            # → 公式计算结果
            sensor.formula, sensor.constants, fbg_delta, ...)
        results[sensor.id] = result
```

**物理量类型**:
- 应变(με): 解耦传感器输出 (`models.py:346`)
- 温度(°C): 解耦传感器输出 (`models.py:347`)
- 自定义公式结果: 普通传感器，用户定义的公式 (如 `W1*k1` → 表观应变等) (`models.py:349-356`)

**每条数据**: `len(df)` 个 float 或 None (None 用于缺失/计算失败)。

### 2. 物理量序列是否进 bundle/chart_data

**❌ 完全未接入。**

搜索结果: `core/chart_bundle.py` 全文无 `sensor_results` 字符串。`from_providers` 的 `AnalysisProvider` 段 (`chart_bundle.py:60-76`) 只读 `analysis_tab_widget._current_data` (原始波长 DataFrame 的前 5 数值列)，**不读** `main_win.sensor_results` (物理量序列) 或 `analysis_tab_widget._sensor_results`。

物理量序列的存储路径 (`main.py`):
- `main.py:884`: `self.sensor_results = cleaned` — 存储在 `DataProcessorWindow.sensor_results`
- `main.py:887`: `self.analysis_tab_widget.set_sensor_results(cleaned)` — 同时存到 analysis_tab_widget

但这两处存储 **都没有通向 `from_providers` 的路径**。

### 3. 物理量分类与计算链路

| 传感器类型 | 产出的物理量 | 计算函数 | 依赖 PhaseB? | 数据结构 |
|-----------|------------|---------|-------------|---------|
| `decoupling` | 应变(με) + 温度(°C) | `_evaluate_decoupling` (`models.py:343`) | **是** — 用 decoupling_config (Ke/KT/S_eff) | 各一个 `List[float]`，长度 = df行数 |
| 普通 (`formula`) | 自定义公式结果 | `_evaluate_sensor_formula` (`models.py:349`) | **否** — 独立公式 (如 `W1*k1`) | 一个 `List[float]`，长度 = df行数 |

`_evaluate_decoupling` 与 `PhaseBWorker.decouple()` **不同**:
- `_evaluate_decoupling` 用的是 `sensor.decoupling_config` (来自公式配置面板的 Ke1/Ke2/KT1/KT2)
- `PhaseBWorker.decouple` 用的是 PhaseA 的 S_eff + PhaseB 的 Ke (来自标定结果)
- 两套参数源 → 两套不同的应变/温度序列

**物理量时程图预期**: 每传感器每物理量一张 (如 A1_应变(με) vs 时间)，或多传感器叠加 (如所有应变在同一张图)。

## B：多源对比模块

### 5. 对比数据装配

**对比结果生成**: `ui/compare_tab.py:1184-1190`:

```python
self._last_comparison = {
    'pairs': pair_results,              # ← 成对对比列表 [{device_a, device_b, corr, rmse, mae, max_error}]
    'device_features': device_features,  # ← {设备名: {mean, std, drift_slope_per_1k, stability}}
    'baseline_method': '窗口首点归零',
    'align_method': '绝对时间插值 (numpy.interp)',
    'n_points': int(len(df_clean)),
    # ★ 注意: 无 'time_h' 和 'sources'!
}
```

**关键发现**: `_last_comparison` 字典**不含 `time_h` 和 `sources`**。但 `from_providers` (`chart_bundle.py:102-108`) 尝试从它读这两个字段:

```python
th = lc.get('time_h')          # ← 永远 None
srcs = lc.get('sources', {})   # ← 永远 {}
if th is not None and srcs:    # ← 永远 False
    bundle.compare_time_h = ...
    bundle.compare_sources = ...
bundle.compare_pairs = lc.get('pairs', []) or []  # ← 这个能读到
```

`compare_pairs` 有值 (标量: corr/rmse/mae/max_error)，但 `compare_time_h` 和 `compare_sources` (原始序列) 从未被写入 `_last_comparison`。

**为什么 `_last_comparison` 不含 time_h/sources**: 原始序列数据在 `compare_tab.py` 的 `FileConfig.annotated_df` 和 `cfg._alignment` 中，但组装 `_last_comparison` 的代码 (`compare_tab.py:1184-1190`) 只存了标量摘要 (pairs/device_features)，没有存原始对齐后的序列数组。

### 6. 对比模块能产的图

| 图名 | 绘图函数 | 所需数据 | bundle 状态 | 原因 |
|------|---------|---------|-----------|------|
| 多源叠加时程 (`compare_ol`) | `make_comparison_overlay` | `compare_time_h` + `compare_sources` | ❌ 半进 | `compare_pairs` 有，但 `compare_time_h`/`compare_sources` 永远空 |
| 成对相关散点 (`corr_*`) | `make_correlation_scatter` | `compare_sources[a]` + `compare_sources[b]` | ❌ 同上 | 同上 |

**结论: 对比模块的所有图都无法产出**，不是因为上游没算（compare 确实跑过了），而是 `_last_comparison` 只存了标量摘要，没有存原始序列。`from_providers` 期待从 `lc.get('time_h')` 和 `lc.get('sources')` 取序列，但这两个键不存在。

### 7. compare_time_h 缺失根因

`compare_tab.py:1184-1190` — `_last_comparison` 组装时漏了 `time_h` 和 `sources`:

```python
# 当前装配: 只有标量
self._last_comparison = {
    'pairs': pair_results,
    'device_features': device_features,
    'baseline_method': '...',
    'align_method': '...',
    'n_points': int(len(df_clean)),
    # 缺失: 以下字段 from_providers 需要, 但未装配
    # 'time_h': 对齐后的时间轴
    # 'sources': 对齐后的各源序列 dict
}
```

这不是保存快照时漏了——是 `_last_comparison` 的**装配代码**本身就漏写了这两个字段。对齐后的序列数据 (`df_clean` / `df_zeroed`) 在同一个函数中存在但未被提取进 dict。

## C：接入评估

### 8. 两类数据源的接入点

**(A) 物理量序列**: 接入点在 `ChartBundle.from_providers` (`chart_bundle.py:60-76`，AnalysisProvider 段)。当前只读 `analysis_tab_widget._current_data` (原始波长前5列)。需新增读 `main_win.sensor_results` (或 `analysis_tab_widget._sensor_results`)，将 `{sensor_id: [value×~98450]}` 写入 bundle 的新字段 (如 `physical_series: dict[str, list[float]]`)。同时需配套时间轴: 物理量序列与原始 df 同长，可直接复用 `bundle.time_h`。

不构成独立前置阶段——`sensor_results` 是 `SensorSystem.calculate()` 的产物，在分析页运行时即已存在，`from_providers` 当前只是没读它。但需确认: `sensor_results` 在诊断保存时是否仍存活 (主窗口是否已关闭/切换项目导致数据被清)。如果存活 → 直接读即可；如果已清 → 需要在 bundle 构造前缓存。

**(B) 对比数据**: 接入点在 `compare_tab.py:1184-1190` — `_last_comparison` 装配处。需补装配 `time_h` 和 `sources` 两个字段。对齐后的序列在装配函数的作用域中 (`df_clean`/`df_zeroed`/`df_interp`)，提取即得。改动在对比模块侧 (`ui/compare_tab.py`)，`from_providers` 的读取代码 (`chart_bundle.py:99-111`) **不需改**——它已经在尝试读这两个字段，只是永远读到空。

### 9. 依赖关系

| 数据源 | 依赖已知挂起项? | 与其他源独立? |
|--------|-------------|-------------|
| 物理量序列 | **是** — decoupling 传感器依赖 `sensor.decoupling_config` (公式配置面板)，与 PhaseB 的 S_eff/Ke 是两套独立参数；不依赖 eps 优先级反转 / 台阶聚合 | ✅ 与 B (对比)、chart_data 现有字段均独立 |
| 对比 time_h/sources | **否** — 仅依赖对比模块自身 (`_alignment` + `df_zeroed`) | ✅ 与 A (物理量)、chart_data 现存字段均独立 |

**不需要等任何挂起项修复**即可接入。
