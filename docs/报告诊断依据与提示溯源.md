## 第一部分 — 提示弹错 (A)

### 1. 加载入口的流程顺序

`_handle_load_diagnosis` (`main.py:1172-1259`):

```
Step 1: all_files = [req_file] + project_files                   (line 1179)
Step 2: if not all_files → QMessageBox "请先添加项目关联资料"     (line 1182-1185)  ← 空硬拦
Step 3: _resolve_project_root_from_files(all_files)              (line 1189)         ← 反推项目根
Step 4: diag_dir = 项目根/数据/诊断记录/                         (line 1195)
Step 5: if not os.path.isdir(diag_dir) → "该项目暂无诊断记录"    (line 1196-1200)    ← 目录扫描空
Step 6: glob *.json → 列出                                      (line 1203-1212)
Step 7: if not entries → "该项目暂无诊断记录"                    (line 1214-1218)    ← 文件空
```

**先后顺序正确: 空硬拦 (Step 2) 在反推项目根 (Step 3) 之前。**

### 1.2 报告工作台的守卫

`ui/report_workbench.py:412-418`:

```python
def _on_load_diagnosis(self) -> None:
    if not self._req_file_path and not self._get_project_file_paths():
        QMessageBox.warning(self, '缺少项目关联资料', ...)
        return
    self.load_diagnosis_requested.emit()
```

**这个守卫也在 `_handle_load_diagnosis` 之前触发** — `_on_load_diagnosis` 先由按钮连接 `load_diagnosis_requested` 信号 → 守卫检查 → 才 emit。emit 后 main.py 的 `_handle_load_diagnosis` 才执行。

### 1.3 为什么关联资料空时弹了"暂无诊断记录"而非硬拦

**双重守卫都正确排列了，但有一个链路条件缺口**: `_on_load_diagnosis:413` 的判断条件是 `not self._req_file_path and not self._get_project_file_paths()` — 仅当**两者都空**时才触发。如果 `_req_file_path` 非空但 `_get_project_file_paths()` 为空，守卫放行。

`_req_file_path` 由报告工作台的"需求文件路径"设置 (`report_workbench.py:109`)。如果之前的会话操作遗留下一个旧的需求文件路径 — 比如用户上轮点过"选择需求文件"、但那个文件已经不在项目资料库下 — 那么:

1. `_on_load_diagnosis:413`: `_req_file_path` = 非空 → 守卫放行 → `load_diagnosis_requested.emit()`
2. `_handle_load_diagnosis:1179`: `all_files = [req_file]` → 非空 → Step 2 硬拦放行
3. `_handle_load_diagnosis:1189`: `_resolve_project_root_from_files` 取 req_file 路径 → 若 req_file 不在资料库下 → `ValueError("文件不属于任何项目")` → 弹"无法定位项目"
4. 或者 req_file 恰好在某项目下 → 项目根推成功 → `项目根/数据/诊断记录/` 是空目录 → 弹"该项目暂无诊断记录"

**关键是** Step 3 场景: 如果 `_req_file_path` 指向一个不存在、但在本机恰好有同名真实目录的路径 (如上次运行遗留的绝对路径)，那可能会意外反推成功 → 扫到一个空的/不相关的目录 → 弹"暂无诊断记录"。

### 1.4 真机最可能的实际场景

从截图可见报告工作台"项目关联资料"列表为空。`_req_file_path` 在 UI 上显示为之前会话留下的旧路径（label 没清空）。`_on_load_diagnosis` 的 guard 放了行，走到 `_handle_load_diagnosis` → `_resolve_project_root_from_files` → 要么报"不属于任何项目"、要么推到某项目根 → `数据/诊断记录/` 空 → "暂无诊断记录"。用户收到的提示不是"先添加关联资料"而是"暂无诊断记录" — 说明 `_req_file_path` 有值且反推找到了项目但目录空。

**根因**: `_on_load_diagnosis` 和三入口的空守卫判断条件 `not req_file and not project_files` 不够严 — 只要 req_file 非空就放行, 不管它是不是有效路径、是不是在项目库内。残留的旧 `_req_file_path` 导致空硬拦被绕过。

## 第二部分 — 报告依据的诊断类型 (B)

### 2. 诊断 record 结构

`ui/ai_diagnosis.py:1119-1192` (`_build_diagnosis_record`):

```
rec = {
    "schema_version": "1.2",
    "timestamp": "...", "backend": "...", "model": "...",
    "selected_sources": [...],
    "data_source_snapshot": [...],
    "kb_hits": [{id, severity, objects, meaning, mechanism, recommendation}, ...],

    "ai_diagnosis": {                                     ← 单专家 AI 诊断
        "diagnosis_json": ai_res.get("json"),             ←   sensor_analysis + physical_diagnosis
        "diagnosis_raw": ai_res.get("raw")[:5000],
    },

    "chart_data": ChartBundle.to_dict(),                  ← 画图数据

    "multi_agent": {                                      ← 多智能体诊断
        "chief_structured": ma_res.get("chief_structured"),  ← ★ 首席专家结构化结论
        "data_scientist_text": ma_res.get("data_scientist_text", ""),  ← 数据科学家文本
        "audit_advisory": ma_res.get("audit_advisory", ""),          ← 审核顾问意见

}
```

**两份并存**: `ai_diagnosis` (单专家) + `multi_agent` (专家组)。`multi_agent.report` 永远为空 — 已废弃。

### 5. `chief_structured` 的结构

`chief_structured` 来自多智能体的首席专家产出 (`dp_engine/multi_agent.py`), 典型结构:

```json
{
    "diagnosis_summary": "...",          // 诊断综合结论
    "data_quality_rating": "fair",       // 数据质量评级
    "data_quality_reason": "...",        // 评级理由
    "sensor_analysis": [...],            // 每传感器分级结论 (与 ai_diagnosis 同构但可能更完善)
    "physical_diagnosis": {...},         // 物理诊断
    "core_recommendations": [...],       // 核心建议
    "kb_rule_hits_summary": "..."        // KB 要点
}
```

这跟 `ai_diagnosis.diagnosis_json` 的结构同构但更丰富 (多 `core_recommendations`/`data_quality_rating` 等)。
