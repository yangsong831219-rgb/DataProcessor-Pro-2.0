## 3. 目录不匹配 — 根因

| 操作 | 目录 | 代码 |
|------|------|------|
| **保存** | `项目资料库/三组标定/数据/` | `ai_diagnosis.py:1290,1296` |
| **加载扫描** | `wiki_vault/diagnoses/` | `wiki_system.py:29,721` |

**两个目录完全不同。** glob 过滤没有前缀限制（`*.json` 匹配任何 json 文件），因此即使前缀不同也不是 root cause——**文件根本不在同一个目录里**。保存到 `项目资料库/{项目}/数据/`，加载扫描 `wiki_vault/diagnoses/`——跨目录不互通。

### 3.1 为什么旧文件出现在列表中

`wiki_vault/diagnoses/` 里实际有这三份旧 JSON：

```
AI诊断_20260620_062759_20260620_062807_981482.json
AI诊断_20260620_080207_20260620_080210_949174.json
AI诊断_20260620_081018_20260620_081023_935406.json
```

它们的前缀是 `AI诊断_`，出现在加载列表里是因为它们在 `wiki_vault/diagnoses/`（扫描目录正确），而不是因为 glob 过滤了 `AI诊断_*`（glob 是 `*.json` 无前缀过滤）。

## 5. 根因指向

**根因 (b) — 保存与加载目录不同。**

| # | 事实 | 证据 |
|---|------|------|
| 1 | 保存写 `项目资料库/{项目}/数据/` | `ai_diagnosis.py:1290,1296` |
| 2 | 加载扫描 `wiki_vault/diagnoses/` | `wiki_system.py:29,721` |
| 3 | glob 是 `*.json`，无前缀限制 | `wiki_system.py:727` |
| 4 | 旧文件在 `wiki_vault/diagnoses/` 所以出现，新文件在 `项目资料库/.../` 所以不出现 | 目录对比 + 文件列表 |

**排除项**：

- **(a) 前缀不匹配**: glob 是 `*.json`，没有 `AI诊断_*` 前缀过滤。旧文件出现的唯一原因是它们在正确的目录里。但这个排除同时说明**即使新文件改回 `AI诊断_` 前缀，只要保存在别的目录就不会出现**——所以根因归到底是目录，不是前缀。
- **(c) 其他**: 无关。

### 5.1 连带发现 — 新 save 路径的另一问题

`_save_diagnosis_to_project` 还调了 `gen_charts_from_diagnosis` 出图到 `项目资料库/{项目}/图片/` (`ai_diagnosis.py:1291,1305`)。这些图片的目录也和报告加载的图片目录无关——图也是"存了但用不上"的状态。

## 6. 修复方向提示（不给方案）

方向只有两个选择：
- **改保存**: 保存到 `wiki_vault/diagnoses/`（跟加载目录一致）
- **改加载**: 加载扫描 `项目资料库/*/数据/`（跟保存目录一致）

改加载意味着 `list_diagnoses` 要递归扫描多个项目子目录下的 `数据/` 文件夹，复杂度高于保存到已知目录。但由于 `_handle_load_diagnosis` 已写好 UI（列表→筛选→JSON 解析），改动范围主要在 `WikiFileSystem.list_diagnoses` 的扫描逻辑。
