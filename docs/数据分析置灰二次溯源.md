# 数据分析诊断置灰二次溯源 — 补行为何未生效

**日期**: 2026-06-25  
**分支**: llama-cpp  
**状态**: 只记现状，不给方案

**背景**: 已在 `_push_annotation_sensor_results`（`main.py:2668`）补 `self.sensor_results = sensor_results`，单测验证通过。但真机数据分析页有数据（曲线/统计/对比均在）时，诊断中心"数据分析"项仍置灰。

---

## 1. `_push_annotation_sensor_results` 的触发时机与 FBG 守卫

**两处调用点** — 均有 `has_fbg` 守卫：

| 调用者 | 文件:行号 | 触发条件 | 守卫 |
|--------|-----------|---------|------|
| `_on_analysis_refresh_requested` | `main.py:2650-2657` | 用户在分析页点"刷新"按钮 | `if annotated_cols and not has_fbg:` |
| `update_data_table` | `main.py:2680-2686` | 文件加载 / 数据表刷新 | `if annotated_cols and not has_fbg:` |

**`has_fbg` 判定** — `main.py:2655` / `main.py:2684`：

```python
has_fbg = bool(self.sensor_system.fbgs)
```

**真机场景**：用户加载的是光纤光栅数据（波长差 W1~W8 列），`FBG_*` 传感器被 `_auto_populate_fbgs(df)` 自动填充（`main.py:2185`）→ `self.sensor_system.fbgs` 非空 → `has_fbg = True`。

**结论**：`_push_annotation_sensor_results` **在 FBG 数据场景下从不被调用**。补的 `self.sensor_results = sensor_results` 那一行是**死代码**——它所在的函数被 `has_fbg` 守卫拦截，从未执行。

## 2. `sensor_results` 在 FBG 路径的唯一写入点

## 4. 诊断面板刷新时机 — 只在 `showEvent` 触发

`_refresh_source_checkboxes()` 被调用的**仅三处**：

| 触发点 | 文件:行号 | 场景 |
|--------|-----------|------|
| `showEvent` | `ai_diagnosis.py:447-450` | 用户**切换到**诊断中心 tab 时 |
| `_on_submit_external_files` | `ai_diagnosis.py:2488` | 提交外部文件 |
| `_on_clear_external_files` | `ai_diagnosis.py:2494` | 清除外部文件 |

**正常操作路径的时间线**：

```
T1: 应用启动 → tab widget 构造 → 诊断 tab 首次 showEvent
    → _refresh_source_checkboxes() → AnalysisProvider.is_available() → sensor_results={} → False → 置灰

T2: 用户加载 FBG 数据 → update_data_table() → has_fbg=True → _push_annotation_sensor_results 跳过
    → sensor_results 仍是 {}（未触发 calculate_sensors）

T3: 用户切到分析 tab → 图表/统计正常（从 _current_data 渲染，不依赖 sensor_results）
    → 诊断 tab 不刷新（离开 tab 后 showEvent 不触发）

T4: 用户切到诊断 tab → showEvent → _refresh_source_checkboxes()
    → AnalysisProvider.is_available() → sensor_results 仍是 {} → False → 继续置灰
```

> **T2→T3→T4 之间 `sensor_results` 没有任何写入机会。** FBG 守卫拦截了补行路径，`calculate_sensors` 未手动触发。

---

## 5. 真因指向

**五项证据汇聚到同一结论**：

| # | 证据 | 指向 |
|---|------|------|
| 1 | `_push_annotation_sensor_results` 两个调用点都有 `if annotated_cols and not has_fbg:` 守卫，FBG 数据下 `has_fbg=True` → 函数从未执行 | **补行位置对 FBG 数据无效** |
| 2 | FBG 路径 `sensor_results` 唯一写入是 `calculate_sensors()`（`:798`），该函数由传感器页"计算"按钮触发，未自动调用 | **FBG 模式需手动"计算"** |
| 3 | 分析页图表从 `_current_data` 渲染（`:440-486`），与 `sensor_results` 无关 | **图表有数据 ≠ sensor_results 有数据** |
| 4 | `_refresh_source_checkboxes` 仅在 `showEvent` / 外部文件操作时调用，不在数据加载/分析刷新后触发 | **面板状态不随数据变化实时更新** |
| 5 | `main.py:349` 初始化 `sensor_results = {}`，`bool({})` = `False` → 从未被覆盖 | **sensor_results 始终为空 `{}`** |

**真因**: **(a) + (b) 叠加** — 补行所在的 `_push_annotation_sensor_results` 被 `has_fbg` 守卫拦截，从未执行（死代码）；FBG 路径 `sensor_results` 需手动 `calculate_sensors()` 才写入，但分析页图表独立渲染不依赖它，用户看到有图表就以为"数据分析有结果了"——实际 `sensor_results` 始终为 `{}`。

**额外发现**：修复后对**通用数据**（TXT/CSV，`has_fbg=False` + `annotated_cols` 非空）是有效的——`update_data_table()` 会在文件加载时调 `_push_annotation_sensor_results`，写入 `sensor_results`。但当前真机测的是 FBG 数据路径，补行始终未被执行。
